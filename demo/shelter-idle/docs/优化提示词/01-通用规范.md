## 一、你在做什么

《末日避难所》是一个**纯文字终端放置小游戏**。使用者只有一个人（就是这台 Windows 电脑的主人），
他几乎没有编程基础，全程由你生成代码。最终交付物是：

- 能在本机终端里用 `node src/game.js` 直接跑起来的 Node.js 程序（工作区内相对路径：`src/game.js` 等）；
- 一份中文使用说明（`README.md`）；
- 一个运行时生成的存档文件（`save.json`）。

**零第三方依赖、零美术资源、不联网、纯文字 + 数字。**

## 二、铁律（违反任何一条 = 本次执行失败）

1. **范围围栏**：只做任务文件里列出的事；发现相邻问题（bug、坏味道、「顺手就能改」）→ 写进报告，不许改。
2. **先读后改**：改任何文件前先读它；禁止凭记忆猜函数名、字段名与配置名，一切以本工作区现状为准。
3. **一步一验**：每个可独立验证的步骤做完立刻验证；失败即停、如实报告，**禁止放宽验收标准**。
4. **数字说话**：所有「能用 / 更快 / 更省」的结论都要附证据（命令与输出、`文件:行号`）。
5. **零依赖**：不许 `npm install`、不许新建 `package.json`、不许引入任何第三方包；只用 Node 内置模块
   （`fs`、`path`、`readline`）。
6. **CommonJS**：本工作区**没有** `package.json`，`.js` 一律按 CommonJS 解析 → 只许用 `require(...)` /
   `module.exports`，**禁止** `import` / `export` / `"type": "module"`。
7. **不省略代码**：禁止「此处略」「按需调整」「其余同理」；生成的每个文件都必须能直接跑。
8. **中文**：所有新增文档、代码注释、界面文案、日志一律中文；中文引号统一用「」，**不得混入 ASCII 直引号**。
9. **只读文件不得改写**：`00-Demo人工步骤清单.md` 只读，只新增文件、不删改已有内容。
10. **提交（可选，看使用者是否同意）**：本工作区位于 git 仓库
    `<REPO>` 内，而仓库根目录在**工作区之外**，提交会写到工作区外的 `.git`。
    所以：**只有使用者当场同意才提交**，提交信息格式 `[shelter] <说明>`；不同意或不确定就**跳过提交**，
    改为在验收报告里写清「本次改动了哪些文件」。
11. **失败即停**：同一个错误试 3 次仍失败 → 记录现场（**报错原文**），交人工裁决。
12. **人工验证边界**：凡需要「新开会话 / 重启 / 在终端里手工输入 / 在浏览器里操作」的验证，**一律由人工执行**；
    你只给精确步骤，等人工回填**原始输出**后如实写入，**禁止推测或「合理补全」**。
13. **产物不出工作区**：所有新增/修改的文件都必须落在本工作区
    （`<REPO>\demo\shelter-idle\`）内；不许写到工作区之外的任何路径。

### 4.1 数值基线（**唯一权威**，后续任务一律照这张表写，不许各写一套）

**初始状态（第 1 天开局）**：天数 `day = 1`；人口 `pop = 3`；食物 `food = 40`；电力 `power = 10`；
四个房间（宿舍 / 水培农场 / 发电机 / 医疗室）等级全部为 `0`（= 未建造）。

**每天推进的结算顺序（固定，不许调换）**：

1. `day += 1`；
2. 发电：`power += 发电机等级 × 4`；
3. 耗电：`need = 水培农场等级 × 2 + 医疗室等级 × 1`；`power -= need`；
   若 `power < 0` → `power = 0`，本日标记「缺电」，第 4 步的农场产出**减半（向下取整）**；
4. 产食：`food += 水培农场等级 × 7`（缺电日减半取整）；
5. 吃饭：`food -= 人口 × 1`；若 `food < 0` → 缺口 = `-food`，饿死人数 = `min(缺口, 人口 - 1)`
   （**至少保留 1 人**，即单日不会因饥饿全灭）；`food = 0`；
   医疗室减免：每级 15% 概率救回 1 人（每天最多救回 1 人）；
6. 人口增长：若 `day % 3 == 0` 且 `food ≥ 10` 且 `人口 < 人口上限` → `人口 += 1`；
7. 事件判定（任务 04）；
8. 结局判定（任务 04）。

**人口上限** = `3 + 宿舍等级 × 3`。

**房间效果与升级成本**（成本是「从上一级升到该级」要付的东西）：

| 房间 | 每级效果 | 升到 1 级 | 升到 2 级 | 升到 3 级 |
|---|---|---|---|---|
| 宿舍 | 人口上限 +3 | 食物 10 | 食物 20 | 食物 35 |
| 水培农场 | 食物 +7/天，耗电 +2/天 | 食物 8 + 电力 5 | 食物 18 + 电力 10 | 食物 30 + 电力 20 |
| 发电机 | 电力 +4/天 | 食物 10 | 食物 22 | 食物 40 |
| 医疗室 | 救回概率 +15%/天，耗电 +1/天 | 食物 15 | 食物 30 | 食物 50 |

**离线收益**：离线每满 1 小时算 1 天，**最多 8 天**（对应 8 小时上限）。
离线只结算资源，**不触发事件、不饿死人**：净食物 = `农场等级 × 7 - 人口`，
净电力 = `发电机等级 × 4 - (农场等级 × 2 + 医疗室等级 × 1)`；负数扣到 0 为止。

**通关与失败**：

- 失败：结算后 `人口 ≤ 0` → 显示「避难所覆灭」结局；
- 通关：`day` 达到 60 并完成当天结算后，若已建成「避难所核心」→ 显示胜利结局；
  未建成 → 显示「撑到了 60 天，但没能建成避难所核心」结局；
- 建造「避难所核心」：需要四个房间**全部 3 级** + 食物 60 + 电力 30。

### 4.2 难度取向

**偏轻松**：正常情况下前 20 天不会崩，玩家按「先发电机、再宿舍、再农场」的常识顺序玩，60 天能通关。

**调参规则（唯一允许改数字的地方）**：若在任务 04 完成后的端到端自检里发现「偏轻松」明显不成立
（例如按常识顺序玩必死，或 40 天就无事可做），**允许且仅允许**调整 §4.1 里的数字，
并在验收报告里写明「改了哪个数字、从多少改成多少、依据是什么」，同时把改后的数字回写进本小节。
**除此之外不许改动任何规则结构。**

   验证结果（逐条验收标准 ✅/❌ + 证据）、关键数据（前后对比）、遗留问题与给下一个任务的注意事项。
   **注意**：`90-报告.md` 已经存在一份由规划阶段预写的骨架，执行任务 90 时是**把 `⬜ 待回填` 换成结论**，
   不是新建文件。
4. **有门就停**：任务 90 标了「验收门」，报告写完后**停下等人工判定**，不要自行做别的。

### 7.2 Windows 终端中文与换行（每次改完界面都要检查）

1. **编码**：写文件一律 UTF-8；`src/game.js` 顶部不要写 BOM。若人工反馈「终端里中文是乱码」，
   第一步是让使用者在 PowerShell 里先执行 `chcp 65001` 再跑游戏，**并把原始输出贴回来**，
   不要凭猜测去改代码。
2. **换行**：终端每行宽度按 **80 字符**设计，超过就要自己折行；状态面板宽度固定 40 个字符（半角），
   中文按 2 个半角宽度算。
3. **不画图**：只用 `=`、`-`、`|` 和中文文字，不用 emoji、不用方框绘制字符（`─│┌` 这类在部分终端会乱码）。

### 7.3 存档安全（任务 03 起适用）

1. `save.json` 写在**工作区根目录**，文件名固定，不要改。
2. 读档时若文件不存在 → 按「新游戏」处理，并打印一行「未找到存档，已开始新游戏」。
3. 读档时若文件存在但内容不是合法 JSON → **不要崩溃**，打印「存档损坏，已按新游戏开始（原文件已备份为
   `save.json.bak`）」，把坏文件改名备份后再开新档。
