> 版本：v0.1（Demo 规划）｜ 日期：2026-10-12
> 适用对象：**几乎没有编程基础**、全程由 AI 生成代码的使用者（就是你本人）
> 配套文档：`docs/优化提示词/01-通用规范.md`（铁律，每个任务开工前必读）、
> `docs/优化提示词/执行进度.md`（跨会话的唯一状态真相）

## 一、这套文件是什么

本目录把「做一个纯文字终端小游戏《末日避难所》」拆成 **5 个可独立执行的小任务**：

- 任务 `01`–`04`：**做东西**的任务，一个任务做完游戏就多一块功能；
- 任务 `90`：**验收门**，专门用来一次性验收「能不能从头玩到 60 天看到结局」。

每个小任务写成 **一个 `.md` 文件**，文件里包含：1. 任务目标 2. 前置条件 3. **一段可直接复制的提示词**
4. 验收标准 5. 常见问题。

**核心工作方式：一个任务 = 一次新对话。** 不要在同一个对话里连着做两个任务——上下文一长，AI 会开始
「顺手多做一点」，那正是最容易把项目做坏的时候。

## 二、开工前的固定准备（每个任务都用到）

| 步骤 | 操作 |
|---|---|
| 1 | **新建对话**，工作区选**本项目根目录** `<REPO>\demo\shelter-idle` |
| 2 | 让新对话先读 `docs/优化提示词/01-通用规范.md`（铁律）与 `docs/工作流程/00-总览与使用说明.md`（本文件） |
| 3 | 打开本任务文件，把「三、提示词」的**整段代码块**复制到新对话发送 |
| 4 | 做完后：按任务文件的「四、验收标准」逐条自检 → 让它写 `docs/验收报告/NN-报告.md` → 回写台账 |

## 三、通用提示词约定（铁律，每个任务的提示词都已内置）

1. **零依赖**：不许 `npm install`、不许建 `package.json`、不许引第三方包，只用 Node 内置模块。
2. **CommonJS**：没有 `package.json` → 只许 `require` / `module.exports`，禁止 `import` / `export`。
3. **纯文字 + 数字**：不许出现任何图片、立绘、音效、动画；终端里只用普通字符画分隔线。
4. **中文**：文档、注释、界面文案、日志全中文；中文引号统一用「」。
5. **数据与逻辑分开**：房间数值放 `data/rooms.js`，事件文案与效果放 `data/events.js`，逻辑放 `src/`。
6. **不省略代码**：禁止「此处略」「按需调整」「其余同理」。
7. **改完即跑**：每次改完至少跑一遍 `node tests/check.js`，并明确说明人工怎么验收。
8. **范围围栏**：只做本任务的事；发现别的问题写进报告，不许顺手改。
9. **产物不出工作区**：所有文件都写在工作区里。

## 七、常见问题

**Q1：AI 说「文件我读不到」。**
先把 `docs/优化提示词/01-通用规范.md` 和本任务文件拖进那个对话。如果它连工作区都没有，说明新建对话时
工作区选错了——必须是 `<REPO>\demo\shelter-idle`。

**Q2：终端里中文显示成乱码。**
先在 PowerShell 里执行 `chcp 65001`，再跑 `node src/game.js`。把**原始输出**贴回对话让 AI 判断，
不要自己猜着改代码。

**Q3：AI 顺手做了后面任务的功能（比如任务 01 就把事件做了）。**
立即叫停，让它把多做的部分**撤回到本任务范围**。多做的部分会污染后面任务的验收证据。

**Q4：`node tests/check.js` 有红字。**
把**完整报错原文**（不是截图、不是「大概是这样」）贴回对话。报错原文是唯一可靠的证据。

**Q5：数字不好玩（太难/太简单）。**
**不要在任务 01–03 里调**。只有任务 04 完成后、走 `01-通用规范.md` §4.2 的「调参规则」才允许改数字，
并且必须写清改了哪个数字、从多少改成多少、依据是什么。

## 八、token 估算（本规划的成本预估）

> 口径：本模式的保守口径 =（输入 + 输出）× **1.5 重试系数**；数字来自 `estimate_tokens` 工具（非口算）。
> **「合计（保守）」列的取法是死规则：合计 = 该行的高值**；「全部任务合计」行 = 各任务高值之和。
> 这是估算不是承诺，实际用量随对话轮次与返工次数变化。

| 估算对象 | 假设规模 | 低 | 高 | 合计（保守） | 是否触发阈值 |
|---|---|---|---|---|---|
| 任务 01 游戏骨架与一天循环 | 6 文件 / 0.5 万字 / 既有代码 5 行 | 0.78M | 2.43M | 2.43M | 未触发 6000 万 |
| 任务 02 房间解锁与三级升级 | 2 文件 / 0.4 万字 / 既有代码 350 行 | 0.77M | 2.40M | 2.40M | 未触发 6000 万 |
| 任务 03 存档与离线收益 | 2 文件 / 0.4 万字 / 既有代码 450 行 / 4 轮迭代 | 1.03M | 3.21M | 3.21M | 未触发 6000 万 |
| 任务 04 事件与通关结局 | 3 文件 / 0.45 万字 / 既有代码 550 行 | 0.77M | 2.42M | 2.42M | 未触发 6000 万 |
| 任务 90 端到端验收 | 1 文件 / 0.25 万字 / 既有代码 700 行 / 2 轮迭代 | 0.51M | 1.60M | 1.60M | 未触发 6000 万 |
| **全部任务合计** | **5 个任务 / 14 文件 / 2 万字 / 既有代码 700 行** | **3.84M** | **12.06M** | **12.06M** | **未触发 2 亿** |

**三列结论**：① 低-高估算 = 3.84M ~ 12.06M；② 合计（保守）= **12.06M**；③ **未触发**「单任务 6000 万」
与「单对话 2 亿」两个阈值 → **不需要二次拆分，也不需要告知式确认**。

**口径备注**：`estimate_tokens` 对「全部任务」单独跑一次给的是低 3.84M / 高 12.01M；上表「全部任务合计」
一行按本模式死规则取「各任务高值之和」= 12.06M，两者差 0.05M，属四舍五入与聚合口径差异。

**一句实话**：这个 Demo 本身很小，按上表的开销口径，**跑本模式可能比直接让 AI 做完还费 token**。
之所以照跑，是因为它同时是「任务规划」模式自己的展示样例（对应仓库任务 07），要拿它验证模式可用性。

## 九、维护约定

1. 任何数字调整都要同时改 `docs/优化提示词/01-通用规范.md` §4.1 与本文件 §八，不允许只改一处。
2. 执行进度只看 `docs/优化提示词/执行进度.md`；对话里说「我做完了」不算数。
3. 想加新功能（例如新房间、新事件）：**不要**在任务 01–04 里顺手加，另起一个带字母后缀的任务文件
   （如 `05A-新事件类型.md`）再做。
