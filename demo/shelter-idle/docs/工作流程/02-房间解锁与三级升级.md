# 任务 02：房间解锁与三级升级

> **阶段**：v0.1 能跑起来
> **前置任务**：01（游戏骨架与一天循环）
> **建议同时提供**：`docs/优化提示词/01-通用规范.md`（铁律与数值基线 §4.1）、`docs/验收报告/01-报告.md`（上一个任务的现场）
> **本任务产出**：菜单里能建造/升级四个房间（每个 3 级），升级后人口上限与每日产出立刻按 §4.1 生效
> **对话方式**：新建对话

---

## 一、任务目标

给骨架装上**成长系统**：四个房间（宿舍 / 水培农场 / 发电机 / 医疗室）从 0 级升到 3 级。

- 新增数据表 `data/rooms.js`，把房间名称、每级效果、升级成本集中放进去（**数字一律照 `01-通用规范.md` §4.1，不许自己改**）；
- 菜单新增「建造 / 升级房间」，列出四个房间当前等级、升到下一级要花什么、资源够不够；
- 升级要真的扣资源，资源不够时拒绝并给出人话提示；
- 升级效果立刻生效：宿舍提升人口上限，农场/发电机/医疗室影响每天的产出与耗电。

本任务不做存档、不做离线收益、不做事件、不做结局。

2. **新建对话**，工作区选 `<REPO>\demo\shelter-idle`，发送下面第三节的提示词。

4. **注意**：`00-Demo人工步骤清单.md` 只读；`src/rules.js`、`src/ui.js`、`src/game.js` 本任务要改，先读再改。

## 五、常见问题

- **升级后效果没生效**：多半是 `advanceOneDay` 里还在用写死的数字，没改成读 `data/rooms.js` 的等级。
  让 AI 把 `src/rules.js` 里产食/发电/耗电那三行原文贴出来对照 §4.1。
- **资源被扣成负数**：说明 `upgradeRoom` 先扣后判断。要求改成「先 `canAfford` 再扣」，并补一条断言。
- **出现两套人口上限算法**：任务 01 已经写过 `getPopulationCap` 之类的函数时，必须复用，不许再写一个。
  让 AI 全局搜一遍「× 3」确认只有一处。
- **AI 说「顺便把存档也做了」**：叫停。任务 03 才做存档，提前做会让任务 03 的验收证据失效。
- **满级房间还能继续升**：检查 `getNextCost` 在 `level >= maxLevel` 时是否返回 `null`，并让菜单据此禁用。
