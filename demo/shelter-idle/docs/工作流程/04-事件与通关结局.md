# 任务 04：事件与通关结局

> **阶段**：v0.3 有目标
> **前置任务**：03（存档与离线收益）
> **建议同时提供**：`docs/优化提示词/01-通用规范.md`（铁律、数值基线 §4.1、调参规则 §4.2）、`docs/验收报告/03-报告.md`
> **本任务产出**：每 7 天一次的事件二选一 + 「建造避难所核心」+ 60 天通关/失败结局
> **对话方式**：新建对话

---

## 一、任务目标

给游戏装上**目标和波折**，让它有始有终。

- 每 7 天（第 7、14、21、28…天）出现一次事件，停下来让使用者二选一，选择真的改变人口或资源；
- 菜单里能建造「避难所核心」（四个房间全 3 级 + 食物 60 + 电力 30）；
- 第 60 天结算完成后判定结局：建成核心 → 胜利结局；没建成 → 「撑到了 60 天」结局；人口归零 → 覆灭结局。

本任务之后游戏功能就齐了，下一步是任务 90 的端到端验收。

## 二、开场准备

1. 确认任务 03（存档与离线收益）已完成：能存档读档、离线收益有上限。
2. **新建对话**，工作区选 `<REPO>\demo\shelter-idle`，发送下面第三节的提示词。
3. 若 AI 读不到工作区，把 `docs/优化提示词/01-通用规范.md`、`docs/验收报告/03-报告.md` 拖进对话。
4. **注意**：事件触发后如果使用者中途退出，存档里要能记住「还没做完的选择」——否则读档会漏掉事件。

## 三、提示词（复制以下整段）

```
我几乎没有编程基础，请全程由你生成代码，所有注释用中文。
继续《末日避难所》项目（Node.js 纯文字终端游戏，零第三方依赖，CommonJS）。

【项目背景】
任务 01–03 已经做出：能开局、推进一天、建造升级四个房间、存档读档、离线收益（最多 8 小时）。
现在要加最后两块：事件系统（每隔几天一次二选一）和通关结局（撑过 60 天并建成避难所核心）。

【已知现场】
第一步：先读 `docs/优化提示词/01-通用规范.md`（**§4.1 数值基线 + §4.2 调参规则**）、
`docs/验收报告/03-报告.md`、以及现有的 `src/state.js`、`src/rules.js`、`src/ui.js`、`src/game.js`、
`src/save.js`、`tests/check.js`；读不到就让我把文件拖进对话。
- 现状：`advanceOneDay` 里第 7 步（事件判定）和第 8 步（结局判定）现在只是占位注释。
- 边界（不在本任务范围）：不做新房间、不做新资源类型、不做联网、不做美术、不做多存档。

【本任务要做的事】
1. 新建 `data/events.js`：导出事件数组，每项含 `key`、`title`、`text`、两个选项
   （各含 `label`、`apply(state)` 与 `resultText`）。四个事件按顺序循环：
   - `survivor`「有幸存者敲门」：① 收留他们 → 人口 +2（**不超过人口上限 +1**），食物 -10（不足则扣到 0）；
     ② 封锁大门 → 食物 +5（搜刮到他们的背包），人口不变。
   - `storm`「暴风雨袭击」：① 花 15 电力加固 → 无事发生；② 不管 → 食物 -20（不足则扣到 0）。
   - `plague`「疾病爆发」：① 花 20 食物开药 → 无事发生；② 硬扛 → 死亡 1 人（人口 > 1 时才死），
     医疗室每级 15% 概率免除这次死亡。
   - `trader`「商人路过」：① 用 30 食物换 15 电力（食物不足则拒绝并说明）；② 不换。
2. 触发时机：`day` 为 7 的倍数时（7、14、21、28…）触发一次事件，按
   `survivor → storm → plague → trader → survivor → …` 循环。
   实现要求：`advanceOneDay` 里**不要**直接调用 `readline`；改成在状态里置一个
   `pendingEvent` 字段（存事件的 key），由 `src/game.js` 的主循环发现 `pendingEvent` 非空时
   暂停菜单、打印事件文字、读入 1 或 2、调用选项的 `apply`、打印 `resultText`、清空 `pendingEvent`。
   **这样存档里能记住「事件还没选」，中途退出再进来会重新问一次。**
3. 菜单新增 `7. 建造避难所核心`（未满足条件时该项显示为「建造避难所核心（条件未满足：…）」并打印缺什么）：
   条件 = 四个房间**全部 3 级** + 食物 ≥ 60 + 电力 ≥ 30；满足则扣 食物 60 / 电力 30，`coreBuilt = true`，
   打印「避难所核心开始运转，只要再撑到第 60 天就能看到结局」。
4. 结局判定（`advanceOneDay` 的第 8 步，结算完成后立刻判断）：
   - `人口 ≤ 0` → 打印「避难所覆灭 —— 你撑到了第 N 天」并结束游戏（正常退出）；
   - `day` 达到 60 且 `coreBuilt === true` → 打印胜利结局，内容包含：天数 60、存活人数、
     四个房间等级、一句鼓励的话；然后结束游戏；
   - `day` 达到 60 且 `coreBuilt === false` → 打印「撑到了第 60 天，但避难所核心没能建成」并结束游戏。
   三种结局都只打印文字、不要求输入，最后一行提示「再玩一次就重新运行 node src/game.js」。
5. 让 `node src/game.js --fast 60`（可选参数，仅用于验收）能自动推进 60 天并把每天的日志摘要打印出来，
   遇到事件时**自动选第 1 个选项**。这是给人工验收用的省时开关，默认不加参数时行为完全不变。
6. `tests/check.js` 至少新增这 7 项断言：
   ① 第 7 天推进后 `pendingEvent === 'survivor'`；
   ② 第 14 天是 `storm`、第 21 天是 `plague`、第 28 天是 `trader`（循环正确）；
   ③ `survivor` 选①后人口增加且不超过上限 +1；选②后食物 +5；
   ④ `storm` 选②食物减 20 且不会变成负数；
   ⑤ `plague` 选②在人口为 1 时不会死到 0（保住最后 1 人）；
   ⑥ 四个房间全 3 级 + 食物 60 + 电力 30 时能建成核心并正确扣资源；条件不足时被拒绝且不扣资源；
   ⑦ `day` 到 60 时按 `coreBuilt` 分别给出胜利结局 / 「撑到 60 天」结局（用 `--fast` 跑一遍验证）。

【硬性要求（不可退让）】
1. 数字只许来自 §4.1 与上面第 1、3 条，**不许自己发明新数值**。
2. 零依赖、CommonJS（只许 `require` / `module.exports`）、不许新建 `package.json`。
3. 界面只准用普通字符，禁止 emoji、彩色控制符、方框绘制字符；所有文案中文，引号统一用「」。
4. 事件文字必须**停下来等使用者输入**，不许自动替使用者选（`--fast` 参数除外）。
5. 不省略代码：禁止「此处略」「按需调整」「其余同理」。
6. **不许**顺手做这些（做了就算本次执行失败）：新房间、新资源、成就系统、排行榜、联网、多存档槽、
   美术/音效、任何测试框架、把 60 天改成别的数字。
7. 不许改动 `00-Demo人工步骤清单.md` 与 `docs/工作流程/` 下的规划文件。
8. 改完自己跑 `node tests/check.js`（全绿）、`node src/game.js --fast 60`（看到结局），
   再手动跑一次 `node src/game.js` 推进到第 7 天确认事件会停下来问。把这三段的**最后几行原始输出**贴给我。
9. 如果你发现「偏轻松」明显不成立（按常识顺序玩必死，或 40 天就无事可做），
   **允许且仅允许**按 §4.2 调整 §4.1 里的数字，并必须在报告里写明「改了哪个数字、从多少改成多少、依据」，
   同时把改后的数字回写进 `01-通用规范.md` §4.1。除此之外不许动规则结构。
10. 提交：**先问我要不要提交**，我说提交再提交，信息用 `[shelter] 任务04 事件与通关结局`。
11. 收尾：回写 `docs/优化提示词/执行进度.md` 任务 04 那一行；写 `docs/验收报告/04-报告.md`。

【本段验收目标】
推进到第 7 天会停下来问「收留幸存者 / 封锁大门」，选完人口或食物真的变了；
能建成避难所核心并在第 60 天看到胜利结局；人口归零会看到覆灭结局；`node tests/check.js` 全部断言通过。
最后告诉我人工如何验收。
```

## 四、验收标准

- [ ] 跑 `node src/game.js` 连点「1」到第 7 天，程序**停下来**问「有幸存者敲门」，等输入 1 或 2
- [ ] 选①（收留）：人口 +2（且不超过上限 +1），食物 -10，日志能看到结果说明
- [ ] 选②（封锁大门）：食物 +5，人口不变
- [ ] 第 14 天出现「暴风雨袭击」，第 21 天出现「疾病爆发」，第 28 天出现「商人路过」
- [ ] 菜单里的「建造避难所核心」在条件不足时显示缺什么；条件满足时能建成并扣掉食物 60 / 电力 30
- [ ] 跑 `node src/game.js --fast 60`，最后能看到结局文字（胜利或「撑到 60 天」）
- [ ] 故意让食物耗尽饿死人到 0（或把人口改成 1 后硬扛疾病），能看到「避难所覆灭」结局
- [ ] 执行 `node tests/check.js`，最后一行是 `CHECK SUMMARY 通过 N / 失败 0`（N ≥ 24）
- [ ] `00-Demo人工步骤清单.md` 与 `docs/工作流程/` 下的规划文件一字未改

## 五、常见问题

- **事件没停下来问，直接过去了**：说明 `advanceOneDay` 里自己把选项选了。这是硬性要求 4 违规，
  要求改成「只置 `pendingEvent`，由主循环来问」。
- **读档后事件丢了**：检查 `pendingEvent` 有没有被写进 `save.json`；没写就补上，并补一条断言。
- **`--fast 60` 跑不到结局**：先看是不是中途人口归零提前结束了（这其实是正确行为，日志里会有覆灭结局）。
- **第 60 天结算后没判结局**：检查结局判定是否放在第 8 步、且在 `day` 自增之后。
- **数值被顺手改了**：如果报告里没有写「改了哪个数字、从多少改成多少、依据」，一律要求改回 §4.1 的原值。
