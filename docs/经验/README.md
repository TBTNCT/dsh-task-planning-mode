# docs/经验 · 实战失误与模式养料

本目录收集**按本项目的任务规划流程开发这个插件时真实踩过的坑**。
和 `docs/实施记录/` 的分工：

| 目录 | 放什么 | 谁读 |
|---|---|---|
| `docs/实施记录/` | 某个任务的**原始材料**：命令与输出、探测结论、中间实验数据 | 复核者 |
| **`docs/经验/`（本目录）** | 把原始材料**提炼成可迁移的教训**，每条都给出"应写成模式里的哪条约束" | **任务 04（写模式系统提示词）的必读输入** |

## 为什么要有这个目录

本插件的目标就是"把模糊想法问清楚、拆成可执行的规划"。**开发它自己的过程就是一次真实的规划实践**——
这次实践里失败的每一处，都对应最终模式里应当防止的一类错误。所以：

- `NN-*.md` 里每一条失误都带一段 **「模式约束建议」**；
- 文件末尾的 **「硬约束候选清单」** 是给任务 04 直接取用的成品；
- **注意**：本目录的文件含本机路径与项目细节，**不要整段抄进模式系统提示词**（将来要开源发布，
  见铁律 8 与 `01-通用规范.md` 用户补充区第 1 条）。任务 04 只提取"约束候选"，并改写成与机器无关的通用措辞。
