## 一、本次失误（按代价排序）

### F1　「环境前提」第二次踩同一个坑（E6 复发，最贵）

- **现象**：会话工作区又是 `<OLD_WORKSPACE>`（任务书§二第 1 条明确要求工作区选 `<REPO>`）。
  F: 是 FAT32（`write` 工具必失败），D: 又在沙箱工作区之外（写入被拒）——
  **一个会话同时失去了"能写的地方"和"该写的地方"**，只能停下等人工裁决（本次人工选择：中途把策略改为 full access）。
- **证据**（原始输出）：
  ```text
  OK   <OLD_WORKSPACE>\.probe-f.tmp
  FAIL <REPO>\.probe-d.tmp :: UnauthorizedAccessException :: 对路径"…"的访问被拒绝。
  FAIL %USERPROFILE%\.dsh\.probe-c.tmp                 :: UnauthorizedAccessException :: 对路径"…"的访问被拒绝。
  FAIL <DSH_DIR>\.probe-droot.tmp                          :: UnauthorizedAccessException :: 对路径"…"的访问被拒绝。
  write 工具 → EISDIR: illegal operation on a directory, link 'F:\…\.probe-write-tool.txt.<pid>…tmpdir\…'
  ```
- **根因**：环境前提（工作区 / 盘符 / 写权限）**在建会话那一刻就定了**，而"确认它"这个动作只在任务书里写着，
  没有一个**开工即执行、失败即停**的固定动作；于是它只能靠"撞墙"被发现。
- **教训**：前提类检查必须是**开场第一个可验证步骤**，而不是任务书里的一句提醒。
- **模式约束建议**：每个任务开场强制输出**环境预检表**（工作区路径 / 盘符文件系统 / 写权限覆盖范围 / 目标路径可达性 /
  包管理器 / 网络），**任一项不合格立即停并要求人工裁决**，并把预检结果留在记录里（本次 §一 已这样做）。

### F2　把「沙箱设计内的越界拒绝」当成「Windows 文件权限（ACL）损坏」

- **现象**：一发现写 D: 被拒，很自然会走"路径 ACL 权限不足 → 修权限"的路子。
- **证据**：拒绝的模式是**按工作区边界**发生的——同一命令写 F: 工作区成功、写 D:/C:/<DSH_DIR> 全部失败；
  这不是某个目录的权限损坏，而是沙箱在按策略拒绝越界写入。
- **根因**：`UnauthorizedAccessException` 这种"像权限错误"的报错，不区分"权限损坏"与"策略拒绝"。
- **教训**：拒绝要**先分型再处置**：越界拒绝 → 停 + 给选项（放行授权 / 换工作区 / 换会话）；
  真的权限损坏 → 才谈修复。**修权限对策略拒绝无效，还可能引入无谓改动**。
- **模式约束建议**：遇到"访问被拒"先做一次**对照组**：同一操作在**允许范围内**是否成功。
  允许范围内成功 + 范围外失败 = 策略/边界问题，**不得**据此修改权限或所有权。

### F3　读取工具与文件编码不一致，造出"文件被写坏了"的假矛盾

- **现象**：同一份 patch 文件，`Select-String` 报最后一行在 **154 行**，`(Get-Content).Count` 报 **114 行**，
  差点据此怀疑写入工具写坏了文件（PS 里中文还显示成乱码）。
- **证据**：本机 PowerShell 是 **5.1**，默认按 ANSI/GBK 解码；
  无 BOM 的 UTF-8 中文文件里，GBK 解码会把多字节序列与紧随的 `0x0A` 一起吞掉 → **行数变少、中文变乱码**：
  ```text
  Count=114  MeasureLines=97        # Get-Content（GBK 解码）
  154: - id: present                # Select-String（按行读取）
  总 155 行                          # read 工具（UTF-8）→ 最终定案
  ```
  文件本身完全正常（`(Get-Item).Length` = 9721 字节，UTF-8 无 BOM）。
- **根因**：**读取工具的编码假设**没有显式指定就用来下"文件内容/行数"的结论。
- **教训**：文件级结论必须绑定读取方式；两个工具读数不一致时**先怀疑工具**，再用第三种（或显式编码）定案。
- **模式约束建议**：凡"这段内容/行数/是否被写坏"这类结论，必须写出**读取命令（含编码）**；
  同一文件两种读法不一致时，先做"哪一种读法显式指定了编码"的判断，不得据此回改产物。

### F4　权限策略会在会话中途变化

- **现象**：开工时策略是 `workspace-write` + 逐次审批；中途被人工改成 `danger-full-access` 且**关闭审批**。
  若 AI 继续按开工假设去申请提权，就会反复触发"自动拒绝"。
- **证据**：策略变更通知两条（"approval policy: ask → never"、"file policy: workspace-write → danger-full-access"）。
- **教训**：**权限是时变的外生事实**，不是会话常量；写工作区之外的路径前要按**当前**策略判断一次。
- **模式约束建议**：涉及工作区外写入时，动作前显式确认"当前策略是否覆盖该路径"；
  策略刚变化后不要沿用旧结论，也不要重复申请已关闭的审批通道。

### F5　把"多帧 zstd 会话日志"当普通压缩文件解，误判"会话是空的/模式是标准"

- **现象**：要复核人工在「任务规划」会话里的工具实测，直接对 `session.v4.jsonl.zstd` 做一次 `zlib.zstdDecompressSync`，
  只解出 **1 行**（`{"type":"session",…,"agentPreset":"standard"}`）——差点据此下两个错误结论：
  ①"这个会话是空的"；②"它是标准模式，实测跑错模式了，证据作废"。
- **证据**（同一文件，两种解法的对比）：
  ```text
  总事件数: 1        # zstdDecompressSync（只解第一帧 = session 头）
  逐帧解码：304 行    # 按 zstd 魔术字 28 B5 2F FD 切帧后逐帧解压
  事件类型: {"session":1,…,"tool/call":45,"tool/result":45,"assistant/message":45,…}
  ```
  而且该文件的真身是**追加写**：写完仍在校验中（文件尾部可能还在变），会话头里的 `agentPreset` 只是**初始值**，
  真正的运行模式要看 `agent-preset/selected` 事件（本例 `seq 3 → task-planning`，早于第一次请求）。
- **根因**：DSH 的会话日志是**按帧追加**的 zstd 流，单次 `zstdDecompressSync` 不会自动续接下一帧；
  同时"会话头字段"与"运行期事实"是两回事。
- **教训**：压缩存档取证前先确认**是否多帧/分段**；把"解出来的条数"当成"文件内容"之前，先用第二种解法交叉验证。
  结论要建立在**运行期事件**（`*-selected`、`tool/call`…）上，而不是初始头字段。
- **模式约束建议**：解析归档/日志类证据时，必须写明"读取工具 + 是否分段"；两类证据（头字段 vs 运行期事件）冲突时，
  以**运行期事件**为准，且两者都要留档。**"解不出内容"不等于"没有内容"**。

## 三、新增「硬约束候选」（接 01 的 12 条，编号 13–19，供任务 04 取用）

13. 开工**第一件事**输出环境预检表（工作区 / 盘符文件系统 / 写权限覆盖 / 目标路径可达 / 包管理器 / 网络），
    任一项不合格**停下要人工裁决**，不得带着不合格前提开工。
14. 「访问被拒」先分型：用**允许范围内的对照组**判断是"边界/策略拒绝"还是"权限损坏"；
    策略拒绝**不得**通过改权限、改所有者来绕过。
15. 涉及文件内容/行数的结论必须写明**读取命令与编码**；两种读法不一致时先怀疑工具，再用显式编码的读法定案。
16. 权限策略是**时变**的：写工作区外路径前确认**当前**策略；策略变化后不沿用旧结论、不重复申请已关闭的通道。
17. 任务书带"版本适用性横幅"时**以横幅为准**，并把正文与横幅的每一处偏离逐条写进报告（不自行改写任务书）。
18. 归档/日志类证据先确认**是否多帧或分段**，写明读取方式；"解不出内容"不得当作"没有内容"；
    **运行期事件优先于初始头字段**，两者冲突时都留档并以运行期为准。
19. 请人工核验前先确认**执行者口径**：需要"人亲自操作"的验收项，不得用"AI 在真实会话里代跑"来顶替；
    若确已由人驱动、AI 代调工具，必须在记录里如实标注执行方式，把它作为**待人工裁决项**而不是既成事实。
