## 一、本次失误（按代价排序）

### F1　落点假设：照任务书正文写"相对路径行"，而它在本机机制下**没有宿主**

- **现象**：任务书正文要求把插件放 `presets/task-planning/plugins/…` 并用 `name: './plugins/token-estimator/index.js'` 挂载。
  横幅已预判"失去宿主"，但**没有给出机制原因**；若照正文做，结果是插件永远不会被加载。
- **证据**（原始输出，实施记录 §2.4）：
  ```text
  --- 行名解析：相对路径行按 loader 语义 new URL(name, baseUrl) ---
  baseUrl = %USERPROFILE%/.dsh/profiles/desktop/
    ./plugins/token-estimator/index.js  => %USERPROFILE%/.dsh/profiles/desktop/plugins/token-estimator/index.js
  ```
  配套源码证据（只读）：`cordis-plugin-loader\lib\index.js:275-278`（相对名 → `new URL(name, this.ctx.baseUrl)`）、
  `dsh-app-boot\lib\index.js:1529`（`ctx.baseUrl = pathToFileURL(dirname(absoluteConfigPath)).href + "/"`）。
- **根因**：`baseUrl` 是 **profile 配置目录**，不是 patch 文件所在目录；"相对路径"在声明式 preset 里**没有"相对谁"的宿主**。
- **教训**：**落点/挂载类结论必须以"本机跑一次"为准**；任务书正文、官方样板、甚至横幅都只是线索，不是证据。
- **模式约束建议**：凡"文件放哪 + 怎么被加载"的结论，必须落成**一条可重放的实测**（改一行 → 跑一次 → 抄原文），
  不得以"任务书这么写的"为依据。

### F2　框架回调里用 `this` 取上下文 —— 静默降级，最难发现

- **现象**：`usage_report` 明明有运行时计量服务在位，却报"运行时计量不可用"。
- **证据**：首版 `execute` 里写 `readRuntimeUsage(this, session)`；宿主是以 `definition.execute(args, exec)` 调用的，
  `this` 是**工具定义对象**而非插件 ctx → `this.get` 不存在 → 走降级分支（**不抛错，所以悄无声息**）。
- **根因**：把"对象方法"的心智模型套到了"框架回调"上；而本插件的设计目标恰是"任何失败都不抛错"，
  于是错误被自己的降级逻辑吞掉了。
- **教训**：降级设计**必须配一条"正向路径的阳性测试"**，否则降级会掩盖 bug。
- **模式约束建议**：框架回调里**禁止用 `this` 取上下文**，一律用闭包捕获；每条降级分支都要有一条"服务在位时必须走正向路径"的测试。

### F3　中文注释/字符串里混入 ASCII 直引号 → 直接 `SyntaxError`

- **现象**：插件首次 import 就崩，报 `SyntaxError: Unexpected identifier '拍脑袋估'`。
- **证据**：描述字符串里写了 `把"拍脑袋估 token"换成…`，ASCII 双引号把字符串提前闭合。
- **根因**：中文行文里习惯性地敲了 `"`，而外层是双引号字符串；同类事故还包括全角/半角混用。
- **教训**：**写完必须真 import 一次**（语法错误只有跑起来才暴露）；中文引号统一用 `「」`。
- **模式约束建议**：含中文的源码/文档，**改完必须有一次真实的解析/运行**；引号用中文标点或统一转义。

### F4　自造校验器报 FAIL 时，先分清"产物错"还是"校验器假设错"

- **现象**：`validate-bundle.cjs` 对本任务的新行报 `FAIL | 安装树里能读到 …/index.js/lib/index.js`，看起来像严重缺陷。
- **证据**：校验器对每行做 `dsh/node_modules/<行名>/lib/index.js` 查找 —— 它的隐含假设是"**每行都是 npm 包名**"；
  本任务的行名是**文件路径**，被拼成了无意义路径。
- **根因**：校验器是任务 01/02 为"全部行都是官方包"的形态写的，输入形态变了而假设没更新。
- **教训**：**FAIL 不等于产物坏**；要把 FAIL 定位到"哪一条假设"，再决定改产物还是改校验器。
- **模式约束建议**：自造校验器的**假设**要显式写进注释；输入形态扩展时同步扩校验器，并把"改前/改后"都留档（本次已做）。

### F5　包的模块类型：没有 `"type"` 字段的包内 `.js` 是 **CJS**

- **现象**：插件若用 `.js` 写在 bundle 里，`export` 语法会失败（bundle 原 `package.json` 无 `"type"`）。
- **证据**：本机另两个可用的本地 bundle（`dsh-boot-animation`、`dsh-whale-widget`）的 `package.json` **都声明了 `"type": "module"`**。
- **根因**：Node 按"最近的 `package.json` 的 `type`"决定 `.js` 的模块类型；无 `type` → CJS。
- **教训**：**跨机制搬代码前先确认包的模块类型与入口字段**，别默认"官方是 ESM，我也是 ESM"。
- **模式约束建议**：新包/新目录放 `.js` 前先确认 `type`；不确定就用 `.mjs` 或补 `"type": "module"`，并把依据写进记录。
