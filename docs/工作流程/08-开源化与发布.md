## 一、任务目标

把仓库变成**别人也能装、也能看懂**的开源项目，并发布到 GitHub。

**必须先认清的一个事实**（决定 README 怎么写）：DSH 的包清单（`dsh` 字段）**不支持声明 preset**。第三方包无法"装上就被识别成模式"。所以分发只有两条真实可行路线：

| 路线 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 复制目录**（推荐，主推） | 把 `presets/task-planning/` 复制到 `%USERPROFILE%\.dsh\.agent-presets\task-planning\` | 零配置、不碰 profile、升级只需再复制一次 | 不是"一条命令装完"；升级要手动 |
| **B. 配置 roots** | 在 profile 的 `cordis.patch.yml` 里给 `agent-presets` 行加 `roots: [{path: <包内 presets 目录>}]` | 装一次就自动跟随包更新 | 必须**重述 `default`**（按 id 的 patch 是整段替换不是深合并）；改错会让所有模式消失；需重启 |

README 必须把两条都写清楚，用 A 作为默认步骤，B 作为进阶。**安全提示必须写**：preset 是一份"组装"，其信任等级等价于 shell 访问；从不可信来源拿 preset 等于让对方在你机器上执行任意组合。

## 五、常见问题

- **`gh` 不在 PATH**：本机装在 `C:\Program Files\GitHub CLI\gh.exe`，可直接用全路径调用；登录需使用者本人完成。
- **push 被拒**：确认 remote 已加（`git remote -v`）、分支名（`main`）与远端默认分支一致。
- **路线 B 改完 patch 后所有模式消失**：这是"整段替换"的典型后果——把 `default` 补回去即可回滚；README 里必须写这个坑。
