## 一、这套文件是什么

本项目要做的是给 **DeepSeek Harness（DSH）** 增加一个新模式：**「任务规划」**，与现有的标准模式、PTC 模式、极简模式、创造模式并列。

这个模式只做一件事：**把使用者脑子里"想要的效果"问清楚，然后拆成可以一段一段执行的规划与提示词**，它自己不动手实现。

DSH 里"模式"的真实身份是 **Agent Preset（智能体预设）**——一个目录、两个文本文件，**不需要编译、不需要写代码就能出现在模式选择器里**。所以本项目的主体是"写对文本 + 接对工具"，而不是"写一个大型程序"。

四个交付物：

| 编号 | 交付物 | 一句话说明 |
|---|---|---|
| A | 模式本体（preset 目录） | `presets/task-planning/`，包含 `preset.yml` + `agent.cordis.yml` |
| B | 模式系统提示词 | 提问流程、需求清单、拆分与估算规则、文档格式规范、11 条硬性约束 |
| C | token 用量估算器插件 | preset 自带的本地 JS 工具插件，提供 `estimate_tokens` / `usage_report` |
| D | 开源仓库 | 双语 README、LICENSE、安装脚本，可被他人安装 |

> Demo（末日避难所挂机）不是第五个交付物，它是**验收手段**：用这个模式真跑一个项目，证明模式产出可用。

## 二、这套文件怎么用（最重要的三条）

1. **一个任务 = 一次新对话。** 做完一个任务、验收通过后开新对话做下一个。这样每个对话上下文干净，结论稳定。
2. **每次对话的第一步：把工作区设为 `<REPO>`**（VS Code 打开这个文件夹；DSH 会话里也选这个目录）。设好之后 AI 自己能读到 `docs/` 下的所有文件，**不需要手动拖文件**。
3. **如果 AI 读不到工作区**，就按每个任务"建议同时提供"一栏列出的文件，把它们拖进对话框。

**为什么不用 `<OLD_WORKSPACE>`？** F: 盘是 FAT32，不支持硬链接，导致 DSH 的 `write` / `edit` 工具在该盘**直接报错**（已实测）。D: 是 NTFS，工具正常。F: 只作为备份与本次规划的原始工作区。

## 四、通用约定

- **铁律**：`docs/优化提示词/01-通用规范.md`，每个任务开工前先完整读一遍。
- **提示词优先级命名**：插件类提示词按名称排序**排在全局提示词之前**——所以本仓库里是 `00-插件提示词-token估算器.md` 先于 `01-通用规范.md`。
- **任务文件内含可直接复制的提示词**：每个 `docs/工作流程/NN-*.md` 的第三节就是一段可整段复制到新对话的提示词。
- **编号规则**：`00` 总览；`01~08` 主线任务按序执行；需要插入任务时用字母后缀（如 `03A`），**不重排已有编号**。
- **失误回流**：每个任务只要出现失误，收尾时就要把**可迁移的教训**写进 `docs/经验/NN-*.md`
  （现象/证据/根因/教训/**对模式的约束建议**）。开发这个插件的过程本身是"任务规划"的一次实践，
  踩过的坑就是最终模式的养料；任务 04 写系统提示词时必须取用 `docs/经验/` 里的硬约束候选。

**合计：约 4.7M – 14.5M token（含可选任务约 5.0M – 15.3M）。**

### 结论（按本模式规则 2.3 判定）

- **没有任何单个任务超过 6000 万 token**，**全部任务总量远低于 2 亿 token** → **不需要二次拆分**。
- 拆分依据不是 token 上限，而是"**一次对话一件事**"：**9 个任务文件 = 8 次实现对话（01–08）+ 1 次可选对话（09）**，避免上下文互相污染。
- 如果某任务实际消耗超过上表上限的 **3 倍**（例如任务 03 的 host 服务探测反复失败），**就在该任务内部再拆**：把"探测并记录证据"与"按证据实现"分成两次对话，并在 `docs/实施记录/` 里留一份探测结论。

## 九、常见问题

**Q1：模式选择器里没有「任务规划」怎么办？**
先确认目录名：`%USERPROFILE%\.dsh\.agent-presets\task-planning\`，里面必须有 `agent.cordis.yml`（顶层必须是数组），目录名只能用小写字母、数字、连字符。然后**新开会话**（预设是在新会话时读取的），必要时重启 DSH 桌面端。

**Q2：模式显示 broken 怎么办？**
在「设置 → Agent presets」里能看到该 preset 的报错原因。常见三种：缺少 `agent.cordis.yml`；YAML 格式不合法（顶层不是数组、某行缺 `name`）；某一行写的包名在本部署里根本不存在（模块解析失败）。修完**新开会话**再看。

**Q3：模式里某个工具不见了？**
工具行是**显式挂载**的：标准模式有的工具，本模式不会自动继承。去 `agent.cordis.yml` 对照 `docs/工作流程/02-工具集接线与实测.md` 的清单补行。注意有些能力（浏览器 UI、进程级单例服务）**不能**放进 preset，见 `docs/调研/01-preset机制.md` 第 E 节。

**Q4：为什么在 F: 盘写文件会失败？**
F: 是 FAT32，不支持硬链接。DSH 写文件时用"临时目录 + 硬链接"做原子替换，所以**在 F: 新建文件的写入（含 `write` 工具）会报错**：`EISDIR: illegal operation on a directory, link ...`（已实测）。`edit` 在 F: 的失败路径**未实测**（其实现可能走 ReplaceFileW/rename）。**本项目统一在 D: 工作**。如果一定要在 F: 写，只能用 PowerShell：`Set-Content -Path <文件> -Value <内容> -Encoding UTF8`（注意 PS 5.1 会写 BOM，需要无 BOM 时用 `[System.IO.File]::WriteAllText($p,$t,(New-Object System.Text.UTF8Encoding($false)))`）。

**Q5：模式开始动手改代码了怎么办？**
这是提示词没写扎实。把 `docs/验收报告/` 里的现场记录（原始输入输出）拿回来，在任务 06 里按"只规划不执行"这条硬约束修正提示词，别在没有证据的情况下反复改措辞。

**Q6：做到一半想加功能怎么办？**
在**这个仓库**里重跑一次「任务规划」模式（新对话即可），让它产出增量规划，然后用字母后缀编号插进 `docs/工作流程/`（例如 `03A-xxx.md`），**不要重排已有编号**，并在 `执行进度.md` 里补一行。
