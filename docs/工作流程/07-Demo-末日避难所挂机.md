## 一、任务目标

用一个**真实但很小**的项目，把「任务规划」模式从头到尾跑一遍，证明：

1. 模式能从一个模糊想法问出可执行的需求；
2. 产出的规划文件能按顺序被**另一个对话**照提示词执行成功；
3. 全程**零美术**（只有文字与数字），符合"本模式不做复杂美术"的定位。

**Demo 题材（已确认）**：*末日避难所挂机*。三句话交代清楚：

- **开局**：你接管一座地下避难所，只有 3 名幸存者；资源是人力 / 食物 / 电力；点一下按钮推进一天，每天自动结算产出与消耗。
- **中期**：用资源解锁房间（宿舍、水培农场、发电机、医疗室），房间提供产能与上限；关闭游戏后仍按离线时长结算收益（有上限，防止无限挂机）。
- **终局**：撑过 60 天并建成"避难所核心"，期间每隔几天出现一次事件选择（收留幸存者 / 封锁大门），不同选择影响人口与资源曲线。

**为什么选它**：零美术、零联网、后端逻辑闭环（资源循环 + 解锁树 + 离线结算 + 事件判定），而"文字放置类"正好是最适合轻量文字模型的品类。

  关闭游戏后按离线时长结算收益，但要有上限，不能无限挂机

## 五、常见问题

- **模式在 Demo 里话太多、问得太细**：这是可改进项，记进"待改进清单"，不要在 Demo 中途去改模式（会污染证据）。
- **对话 ② 执行失败**：这是**最有价值的证据**——说明模式产出的提示词不够可执行。如实记录报错原文与修法，进"待改进清单"。
- **Demo 越做越大**：只允许执行 Demo 的**第一个**任务。Demo 的目的是验收模式，不是把游戏做完。
