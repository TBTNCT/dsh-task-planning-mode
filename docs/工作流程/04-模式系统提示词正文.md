## 一、任务目标

写出「任务规划」模式的**系统提示词正文**——它是这个模式的灵魂：模式像不像"一个懂流程的规划师"，全看这份文字。

同时解决一个工程问题：**这么长的提示词怎么维护**。

**推荐做法（有回退）**：把正文写成独立文件 `presets/task-planning/PROMPT.md`，然后在 `agent.cordis.yml` 的 persona 行里用 `!!js` 在配置求值时读文件内容——这样提示词可被 VS Code 正常编辑、可 diff、可被 git 管理，不必塞进 YAML 的缩进地狱。

参考写法（官方创造模式里用过同一个机制，见 `presets/cordis/agent.cordis.yml` 的 `!!js "...new URL('skills/', baseUrl)"`）：

```yaml
- id: persona
  name: '@deepseek-ai/dsh-persona'
  config:
    prefix: !!js "process.getBuiltinModule('node:fs').readFileSync(new URL('PROMPT.md', baseUrl), 'utf8')"
```

> ⚠️ persona 行**不要**写 `suffix: Your working directory is {{cwd}}.`：persona 段的模板只注册
> `{{provider}}` / `{{model}}`，`{{cwd}}` 未注册，会在任何模型请求之前抛
> `unknown prompt variable "{{cwd}}"` 让整个 prompt 组装失败（2026-10-18 实测）。
> 工作目录由运行时上下文（working-directory 服务）作为必需上下文注入，不需要写进模板。

**如果这段 `!!js` 挂载失败**（baseUrl 不可用、路径解析不到、YAML 报错）：退回把正文**内联**进 YAML 的块标量（`prefix: |`）。两种做法都要在记录文件里写明最终采用的是哪种、为什么。

### ⚠️ 生效口径（必读，否则会误判"写了没用"）

preset 的**重组代际只以 `agent.cordis.yml` 的 mtime + size 为键**（依据：
`dsh-agent-presets/lib/index.js` 的代际判定与 `cordis-plugin-loader` 的配置求值时机），
而 `prefix` 的 `!!js` 只在**挂载激活时求值一次**。因此：

- **只改 `PROMPT.md`、不改 `agent.cordis.yml`，新开会话也不会生效**；
- 必须**同时触碰 `agent.cordis.yml`**（例如加一行注释保存、或改一个空格）以改变 mtime/size，
  或者重启 DSH，然后**新开会话**。

**因此要求一个"哨兵"机制**：`PROMPT.md` 第一行写一句可判定的标记，例如
`<!-- PROMPT-SENTINEL: v1 -->`，并且在正文里让模式在被问到时复述该标记。
每次改完提示词后，用"模式能不能复述出当前哨兵值"来判断是否真的生效——
不要用"感觉它变了"来判定。

如果实测发现"触碰 `agent.cordis.yml` 仍然不生效"，就**改用内联**（把正文放进 YAML 块标量），
并在记录里写明原因；不要在这个机制上反复试超过两轮。

## 五、常见问题

- **`!!js` 读文件失败**：先确认 `baseUrl` 在该行 config 里可用（官方 cordis preset 用过）；再确认相对路径是相对 preset 目录。都不行就内联，别在这上面耗超过两轮。
- **模式不提问、直接开写**：把"提问优先"写成**硬触发条件**（例如"在需求清单未达到 x/9 且用户未喊停之前，禁止输出任务拆分"），而不是语气词。
- **提示词太长导致模式"记不住"**：把必须遵守的部分（11 条硬约束 + 提问流程 + 估算口径）放在最前与最后各一次——首尾双写比加长中间段落有效。

> 1.模式意义：本模式仅用于规划任务及生成提示词，不负责执行任务，本模式是为了将使用者大脑中已有的明确想法进行实现而做，面向那些没有任何对将要实现的想法进行专业训练或业余训练的人，即完全不了解该想法所对应的行业，但是明确知道自己想要什么效果的人。
> 2.模式规则：
> （1）对提出的要求进行解析，向使用者尽可能详细的提问其要求的具体细节（可以进行多轮提问，直到大致框架能够成型和最终结果大致明晰为止）
