# 任务 05：文档格式模板与首次自测

> **阶段**：v1.0 核心（产出长得对）
> **前置任务**：04
> **建议同时提供**：`docs/调研/04-规划文档格式.md`、`docs/工作流程/04-模式系统提示词正文.md`
> **本任务产出**：`presets/task-planning/skills/planning-templates/SKILL.md`（5 类骨架）、`PROMPT.md` 中的模板加载要求、玩具需求自测产物、`docs/验收报告/05-自测报告.md`
> **对话方式**：新建对话

## 一、任务目标

模式现在会提问、会规划，但**产出的文件骨架还靠模型即兴发挥**——同一个模式两次跑出来的文件名和章节可能不一样。本任务把骨架**固化**，并用一个玩具需求验证。

**5 类骨架**（来自 `docs/调研/04-规划文档格式.md` 的结论）：

| 骨架 | 用途 | 对应文件 |
|---|---|---|
| 总览与使用说明 | 项目门面 + 任务清单 + 依赖图 + 验收节奏 + 常见问题 | `docs/工作流程/00-总览与使用说明.md` |
| 任务文件 | 一个任务 = 一次对话（5 字段信息头 + 五节正文） | `docs/工作流程/NN-<短语>.md`（例如 `01-仓库地基与预设骨架.md`；**不写"任务"二字**） |
| 通用规范 | 项目铁律 + 用户补充区 + 收尾四步 | `docs/优化提示词/01-通用规范.md` |
| 执行进度台账 | 五态标记 + 6 列表头，每任务一行 | `docs/优化提示词/执行进度.md` |
| 验收报告 | 做了什么 / 验证结果 / 遗留问题 | `docs/验收报告/NN-报告.md` |

**关于放哪里**（重要取舍）：骨架是几千字的**可复制文本**，如果全部塞进系统提示词，会让**每一次请求**都多付几千 token。所以骨架放在 **preset 自带的 skill** 里（`presets/task-planning/skills/planning-templates/`），系统提示词里只写"结构规范 + 产出文档前必须加载该 skill 取骨架"。这是唯一一处对"全部写进系统提示词"的偏离，理由与代价要写进记录。

## 五、常见问题

- **skill 没出现在模式的 skill 列表里**：检查 `customSkillDirs` 的 `!!js` 写法与 frontmatter；skill 目录名与 `name` 字段不要求一致，但都必须合法。
- **自测时模式不肯停**：这正是要记录的偏差——把"用户喊停立即转规划"的措辞在 `PROMPT.md` 里改成可判断的触发条件，然后重测一项。
- **产物写在 F: 或官方目录**：明确要求模式只在当前工作区写文件；把这条加进系统提示词的"只规划不执行"段。
