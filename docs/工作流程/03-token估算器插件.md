## 一、任务目标

给「任务规划」模式加一个**自带的本地工具插件**，让模式不再"拍脑袋估 token"，而是有两条轨：

1. **运行时计量轨**：读 DSH 已有的会话用量（能读到就读）；
2. **静态估算轨（兜底）**：按工作区文件字数 + 项目规模参数算区间。

对外暴露两个工具：

| 工具名 | 输入 | 输出 |
|---|---|---|
| `estimate_tokens` | 阶段描述（文本）、规模参数（文件数 / 是否含前端 / 是否含游戏逻辑等） | 低-高区间、合计、是否触发 60M/200M 规则 |
| `usage_report` | 可选：会话 id / 任务编号 | 本会话已用 token（若运行时计量可用）+ 与预估的对照 |

**读不到运行时计量不算失败**：工具必须返回静态估算，并注明"运行时计量不可用（原因）"。

## 二、⚠️ 本任务最大的坑（先看这一节，别跳）

**preset 目录在用户 home 下，Node 的向上 `node_modules` 查找走不到 harness 的依赖。**
因此**照抄官方包的 `lib/index.js` 会立刻挂载失败**——例如 `@deepseek-ai/dsh-tool-todo` 的第 1~3 行就是
`import ... from '@deepseek-ai/schemastery'` / `'zod'` / `'@deepseek-ai/dsh-tools'`，
这些**裸包导入在 preset 目录里解析不到**（preset 只对"行名"的包名解析做了兜底，对**模块文件内部的导入没有兜底**）。

**所以本任务的第一件事不是写插件，而是做"最小挂载实验"**，把三种载入方式的实际可行性测出来：

| 实验 | 做法 | 预期 |
|---|---|---|
| E1 | 相对路径行 `name: './plugins/probe/index.mjs'`，插件内**只用 `node:` 内置 + 相对导入** | 应当成功 |
| E2 | 同上，但插件内 `import { z } from 'zod'`（裸导入） | 预期失败——失败也是结论，记录下来 |
| E3 | preset 内放 `package.json`（`"type": "module"`）后用 `index.js`；以及裸包名行（插件做成 npm 包/link 到 profile） | 记录哪种可行、代价是什么 |

**依据 E1~E3 的实测结论再决定实现方式**；如果 E1 成功，就用"零依赖 + 内联一切"的写法。

## 六、常见问题

- **插件挂载后模式 broken**：先看是不是裸导入（E2 那个错）；再看行 name 的相对路径写法是否与文件实际位置一致。
- **读不到计量服务**：不算失败。preset 是"一个会话的组装"，宿主平面服务不一定可见；按降级实现并记录结论。
- **改了插件代码没反应**：preset 的重新组装以 `agent.cordis.yml` 的变更（mtime+size）为键——改了插件文件后要**同时触碰 `agent.cordis.yml`**（例如加一行注释再删掉）或重启 DSH，然后**新开会话**（此步人工执行）。
- **想让插件用官方工具包**：先证明"裸包名行 + 独立包"这条路可行；否则不要为了省事而引入必然失败的 import。
