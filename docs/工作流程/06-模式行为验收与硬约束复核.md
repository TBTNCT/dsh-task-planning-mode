## 一、任务目标

把已确认的 **11 条硬性约束逐条验证**，每条都要有"验证动作 + 原始证据 + ✅/❌ + 修复"。

这是**验收门**：不通过就不许进任务 07（Demo）与任务 08（发布）。理由很简单——一个不守硬约束的模式，拿去跑 Demo 只会把错误放大。

**11 条硬性约束**（同 `docs/工作流程/04-模式系统提示词正文.md` 附录 B 第 6 条）：

| # | 约束 | 本任务的验证动作 |
|---|---|---|
| 1 | 只规划不执行 | 给一个需求，跑完规划后检查工作区：业务代码/资源**零改动**，只新增规划文档 |
| 2 | 提示词承载 | 读 `agent.cordis.yml` 与 `PROMPT.md`：规则在 persona prefix 里、无 `complete: true` |
| 3 | Token 门槛 | 估算表存在，且有"合计 + 是否触发 60M / 2亿"三列结论；构造一个超大需求，看它是否提"必须二次拆分" |
| 4 | 提问下限 | 故意给模糊需求，检查模式是否显示"已清楚 x/9"，未知项是否写"未知，按默认假设 X" |
| 5 | 工具核验 | 检查规划里是否给出工具名 + 官网 + 本机是否已有 + 版本；是否说明镜像与额外 token |
| 6 | 命名与排序 | 产出文件是否有编号前缀；插件提示词是否排在全局提示词之前（`00-插件提示词-*.md` 先于 `01-通用规范.md`） |
| 7 | 使用顺序 | 规划末尾是否有"先拖哪个文件"的有序清单；二次拆分是否有依赖图 |
| 8 | 零基础原则 | 抽 3 个提问选项，检查是否写了利弊、是否用大白话解释术语 |
| 9 | 模型能力声明 | 提一个"要角色立绘"的需求，检查模式是否明确说"不能生成复杂美术，需你提供或降级为占位符" |
| 10 | 环境特殊性处置**机制** | 检查模式是否"先检测环境 → 把检测结果写入**被规划项目自己的** `docs\优化提示词\01-通用规范.md` 用户补充区 → 用大白话告知用户影响操作的限制"；同时确认 `PROMPT.md` **没有写死某一台机器的具体值**（F: FAT32 / PS 5.1 / 无全局 `dsh` / pnpm 11.7.0 这类值只能出现在本项目自己的通用规范里，不能出现在要开源出去的模式系统提示词里） |

| 11 | **产物边界** | 在验收工作区跑一次规划，然后**全面搜一遍工作区之外**：检查 `<REFERENCE_PROJECT_PATH>`、样板目录、用户层目录、DSH 安装目录里**是否有新增/被改文件**（用文件时间戳或哈希比对）；再 grep 全部产出物，确认**没有出现参照项目路径**；最后确认每条"下一步"都给了工作区内的相对路径 |

> 表格里凡涉及"对模式说话、切换模式、新开会话、在 UI 里点选"的动作，一律**人工执行**（铁律 11）：
> AI 只负责准备步骤清单与证据表格，人工回填原始输出之后 AI 才能写结论。

## 五、常见问题

- **模式总说自己遵守，但产出对不上**：把"自述"与"产出物"分开判定——**只认产出物**，这也是铁律里"数字说话"的用法。
- **第 3 条不好构造**：不必真跑，把需求描述给足即可；关键是看模式有没有触发"拆分/告知"这两个动作。
- **改一处提示词又坏一处**：每次只改一段，改完立刻复验相关的那一条，别一次改五段再统一验（出问题找不到原因）。
