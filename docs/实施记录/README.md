# docs/实施记录 · 用途与命名

本目录存放**原始证据留档**，与 `docs/验收报告/` 分工不同：

| 目录 | 放什么 | 谁读 |
|---|---|---|
| `docs/验收报告/NN-报告.md` | **结论**：做了什么、逐条验收标准的 ✅/❌ 与证据、关键数据、遗留问题、人工判定栏 | 人工验收时读 |
| `docs/实施记录/NN-<短名>.md`（本目录） | **原始材料**：命令与原始输出、探测结论（含 `file:line` 证据）、接线记录、中间实验数据 | 排查与复核时读 |

## 命名

`NN-<短名>.md`，NN 与 `docs/工作流程/` 下的任务编号对应。已规划的文件：

| 文件 | 由哪个任务产出 | 内容 |
|---|---|---|
| `01-骨架安装记录.md` | 任务 01 | git init、preset 最小骨架、安装到用户层的命令与结果 |
| `02-工具实测表.md` | 任务 02 | 标准档 10 项能力的实测表（含人工回填的原始输出） |
| `03-token估算器实测.md` | 任务 03 | E1/E2/E3 最小挂载实验结论、计量服务探测结论、两个工具真实输入输出 |
| `04-提示词接线实测.md` | 任务 04 | 接线方式（`!!js` 还是内联）、哨兵生效验证、字数与 token 粗估 |
| `05-模板接线记录.md` | 任务 05 | 模板 skill 的挂载方式与实测结果 |
| `07-模式待改进清单.md` | 任务 07 | Demo 暴露出的模式问题（现象 / 影响 / 建议改法） |
| `09-npm壳包评估.md` | 任务 09（可选） | 三种 npm 形态的取舍与建议 |

## 硬性要求

1. **原始输出照抄**：命令输出、报错栈、类型定义片段一律原文粘贴（截断到关键行即可），不要转述。
2. **标来源**：每条记录标明"AI 机器验证"或"人工执行（执行人：<用户名>）"。
   需要新开会话 / 切换模式 / UI 点选的动作，**只能由人工执行**（铁律 11）——AI 不许代填。
3. **失败的实验要留档**：失败的路径（例如插件内裸包导入必挂）同样是有价值结论，必须写进来，
   并附报错原文。
4. 本目录的文件**不必逐字工整**，但要可复核：别人照着你的记录能重放一遍。
