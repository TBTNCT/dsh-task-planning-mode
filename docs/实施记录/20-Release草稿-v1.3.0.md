# v1.3.0 · 估算 ×20 校准 + 并行与子代理 + 任务执行流程图 + 收尾交接

> 本文件是 Release 正文草稿（仓库惯例：每版 Release 留一份成文，见 `07-Release草稿-v1.0.0.md` / `10-Release草稿-v1.1.0.md` / `12-Release草稿-v1.2.0.md`）。

**这版不新增"功能开关"，改的是三件会让规划更贴近真实的事**：估算不再低报、并行不再靠自觉得到许可、规划产出多了一张能点的流程图。

1. **token 估算统一 ×20 校准** —— 之前所有估算都**低报约 20 倍**（按 ds4.1f 实测消耗反推）。现在倍率写在插件里（`CALIBRATION_FACTOR = 20`），**只乘在 `raw` 一行**，`LOW_FACTOR` / `HIGH_FACTOR` / `RETRY_FACTOR` 的语义一个字没动。6000 万 token 的**拆分阈值不变**，但因为数字变真实了，**更容易触发拆分**——这是正确行为：**触发就拆，不许为了让数字好看去调系数或抬阈值**。
2. **并行与子代理写实** —— 允许互不依赖的任务并行、允许要求用子代理执行，但给了五条硬判据（写入范围不重叠 / 必须回主会话复核 / 依赖与接口先对齐 / 单列组装验收 / 上限 2 个会话）；**没有子代理时必须写「无子代理，已串行」**，不许标了并行却串行做完还说并行过。
3. **新增必须产出物 `docs/工作流程/00-任务执行流程图.html`** —— 编号 `00`（它不是任务），由模板生成，只替换数据块；能看进度条、依赖边、并行批次、五种状态和「下一个该做的任务」。
4. **任务文件新增必填第六节「六、收尾交接」** —— 每个任务结尾必须用提问工具逐条问人工决策（**不许 AI 自行决定**）+ 给出下一个任务的预计耗时（区间 + 依据）。

## 升级（DSH 0.2.x，实测路径）

> 本版**改了提示词、插件与 `cordis.patch.yml`**（新增 `touch` 行），所以**不必卸载重装，完全退出重启即可**让 preset 重组。

1. **不需要卸载重装**。若更习惯覆盖安装，也可在插件管理器重新粘贴本仓库 `presets/task-planning-bundle` 的**绝对路径**再装一次
2. **完全退出桌面端**（不是关窗口；托盘退出 + 任务管理器确认无残留进程），再启动
3. 新开会话 → 模式选择器选「**任务规划**」→ 问「**当前哨兵值是多少？**」，
   应逐字回答 `<!-- PROMPT-SENTINEL: v11 -->`
4. （可选，数字面）调一次 `estimate_tokens`，渲染文本应含「**校准：×20（本估算基于 ds4.1f 消耗计算）**」，
   且数值为**千万级**而非几十万级
5. （可选，行为面）说「我想做个记账小工具」，看它是否**先给「版本迭代规划表」并问划分对不对**，而不是立刻问第一题

> 答 `v10` 或答不出 = 没生效。此时**不要反复重启试**，按 `presets/task-planning-bundle/README.md`
> 第四节第 7 条排查（关键是确认改的是 `cordis.patch.yml`，而不只是改了 `PROMPT.md`）。
> 安装报 `ERR_PNPM_UNEXPECTED_STORE` 的修法也在同一份 README。
