
## 三、⚠️ 真正的问题：npm 公开元数据里有你的 QQ 邮箱

registry 上 `dsh-task-planning-preset` 的**公开元数据**（任何人访问 `https://registry.npmjs.org/dsh-task-planning-preset` 都能看到）：

```json
"maintainers": [{ "name": "<npm_user>", "email": "<EMAIL_REDACTED>" }]
"_npmUser":   { "name": "<npm_user>", "email": "<EMAIL_REDACTED>" }
```

**这是 npm 机制决定的**：发布者的账号邮箱会被写进包的 maintainer 字段，且**随每个版本永久公开**。
它**不在包文件里**（tarball 里 0 命中），但**在 registry API 里**。

### 影响评估

| 维度 | 说明 |
|---|---|
| 泄露内容 | QQ 邮箱 1 个 + npm 用户名 `<npm_user>` |
| 是否可被反查 | QQ 邮箱 → 可加 QQ / 可搜到关联账号；比 `noreply` 邮箱暴露面大 |
| 是否已在别处公开 | 该 npm 账号本身的资料页本来就公开展示用户名与邮箱 |
| 能否事后清除 | **已发布版本的 maintainer 记录无法删除**；只能改账号邮箱后，**新版本**用新邮箱 |
| 严重程度 | 中低。不是凭据、不是 SID、不是家目录；但属于规范第 ② 类「身份」 |

### 处理选项（需你决定）

| 方案 | 做法 | 效果 | 代价 |
|---|---|---|---|
| **A. 忽略** | 什么都不做 | 邮箱继续公开 | 0 |
| **B. 改 npm 账号邮箱为 GitHub noreply** | npmjs.com → Account Settings → 改 email 为 `325988531+TBTNCT@users.noreply.github.com` → 之后发新版本 | **新版本**的 maintainer 显示 noreply 邮箱；旧版本 `1.2.0` 记录不变 | 需验证新邮箱（要能收 GitHub noreply 域的信——通常不可收信，npm 可能要求验证，这是主要障碍） |
| **C. 只改公开资料，不改账号邮箱** | 部分账号可在 profile 里隐藏邮箱 | 不确定 npm 是否支持隐藏 maintainer 邮箱 | 需在网页确认 |

> **本文已按规范占位化**：文档里的邮箱写成 `<EMAIL_REDACTED>`、npm 用户名写成 `<npm_user>`——
> 这是「记录文字不要二次泄露」的自觉处理（v1.1.0 发布记录里踩过同一个坑：
> 把敏感字面量抄进 CHANGELOG 后被门禁自己扫出来）。原文形状保留，可复核性不受影响。
>
> **重要**：npm 的 maintainer 邮箱来自**账号设置**，不是 `package.json`。
> 在 `package.json` 里写 `"author"` 或 `"maintainers"` **不能覆盖**它——registry 会用自己的账号信息。
> 所以「清洗」在这个面上只能通过改账号设置，不能通过改仓库文件。

## 七、结论

- **「是否确定清洗了」→ 代码与文档层面：确定。** 已发布包内 0 处用户名 / 邮箱 / SID / 凭据 / 家目录，
