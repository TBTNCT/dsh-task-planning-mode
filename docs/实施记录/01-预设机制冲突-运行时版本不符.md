### 2.2 找到真正的原因：桌面端加载的是**另一份、更新版的 DSH**

- 崩溃日志（`%APPDATA%\@deepseek-ai\dsh-desktop\logs\crash-2026-10-01T15-00-04-898Z-host.log`）原文：
  `dsh: skipping profile bundle "@deepseek-ai/dsh-experimental-agent-team-web-profile": Error: dsh: cannot resolve profile bundle "…" from the dsh installation or %USERPROFILE%\.dsh\profiles\desktop`
  → **profile bundle 的解析顺序是「先安装目录（asar），后 profile 目录」**，asar 里的那份优先。

## 三、结论

1. **任务 01 第 4 步「复制到 `%USERPROFILE%\.dsh\.agent-presets\task-planning\`」在本机运行时上完全无效。**
   新版注册表不扫描目录、不接受 preset 路径；该目录里的 `preset.yml` / `agent.cordis.yml` 是死数据。
2. 因此验收标准第 3/4/5 项（🔸选择器出现「任务规划」、可用 `ask_user_question`、可用文件读写）**在当前机制下不可能通过**；这不是配置写错，也不是"再重启一次"能解决的。
3. **前提不成立的范围**（需要人工裁决是否重做规划，AI 不擅自改）：
   - `docs/调研/01-preset机制.md` 全部基于 `@deepseek-ai/dsh-agent-presets@0.1.5-rc.2`（`<DSH_INSTALL>` 那份），**不适用于本机运行的 `dsh-web-app@0.2.1-alpha.1`**。
   - 任务 02「标准档工具行全部接进 preset」的落点：新版里工具行写在 **preset 声明的 `config.plugins` 里**（形态与旧 `agent.cordis.yml` 的行几乎一样，可平移），不再写 `agent.cordis.yml` 文件。
   - 任务 03「preset 自带本地 JS 插件 `./plugins/…`」：新版**没有"preset 目录"概念**，相对路径行失去宿主；要重新设计分发方式（bundle 包 = 一个带 `dsh.bundle.patch` 的 npm/本地插件包，或把插件代码放进该 bundle 包内）。
   - 任务 08/09 的「安装脚本复制目录到 `.agent-presets`」「npm 壳包挂 `roots`」同样需要按新机制重写。
4. **本轮我没有做的事**（铁律 1/12/7）：没有改 `docs/调研/*`、没有改任何任务文件、没有写 `%USERPROFILE%\.dsh\profiles\...`（那是铁律 12 明令禁止的路径）、没有改 asar 里的任何官方文件、没有删除已安装的死目录。

## 四、可走的路线（供人工裁决，AI 不代选）

> 三条都需要人工先改一次规划（或明确授权 AI 改），因为都偏离现任务书的机制假设。

**路线 A（推荐）：按新版机制重做任务 01**
- 交付物从「一个 preset 目录」改为「**一个 profile bundle 插件包**」，形如：

  ```text
  presets/task-planning-bundle/
    package.json        # { "name": "dsh-preset-task-planning", "dsh": { "bundle": { "patch": "./cordis.patch.yml" } } }
    cordis.patch.yml    # - insert: [ { id: preset-task-planning, name: '@deepseek-ai/dsh-agent-preset',
                        #             config: { id: task-planning, name: 任务规划, description: …, order: 5, plugins: [ … ] } } ]
  ```
- 现有 `presets/task-planning/agent.cordis.yml` 里的行清单（persona / tool-ask-user / tool-fs / tool-fs-search / compaction 组）**可以整段平移**到 `config.plugins`；`preset.yml` 的 name/description/order 平移为 `config.name/description/order`。已做的工作不作废。
- 安装方式：用 DSH 的插件管理器把该 bundle 装进 `desktop` profile（桌面端 UI「插件 → 添加插件」，或 `dsh plugin --profile desktop install <路径>`）。**这一步会写 `%USERPROFILE%\.dsh\profiles\desktop\`，属于铁律 12 的禁区** → 需要人工在 UI 里操作，或明确授权 AI 例外执行。
- 优点：与官方推荐路径一致（README 明确说"新建 preset 都是 bundle 补丁 + plugin_manager 安装到 profile"）；缺点：安装动作必须有人参与。

**路线 B：用应用内的「创造模式」写 preset**
- 设置 → Agent presets 的「创造入口」会开一个 `cordis` preset 的会话，由它在对话中生成并安装 bundle。本机桌面端 profile 里已装 `@deepseek-ai/dsh-experimental-agent-team-*`、`cordis` 相关包（`dsh-node_modules` 清单可见 `dsh-agent-preset/skills/cordis-plugin-development` 等）。
- 优点：全程走产品自己的机制，不需要我们直接改 profile；缺点：产物的可复现性取决于对话过程，本项目的"文档 + git 仓库"式交付要重新设计。

**路线 C：降级 DSH 到仍支持旧机制的版本（0.1.5 系列）**
- 只有这样才能继续沿用现任务书（目录 + `agent.cordis.yml` + `.agent-presets`）。
- 代价：升级会被覆盖（呼应 `docs/调研/01-preset机制.md` C.4 的"升级会覆盖 shipped preset"），且要用户自己重装桌面端；不建议。
