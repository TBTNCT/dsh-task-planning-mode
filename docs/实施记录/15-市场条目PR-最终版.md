### ⚠️ 为什么条目里**不能**写 `npm:` 字段

对方 `scripts/lib/entries.mjs` 的 `ENTRY_KEYS` 只允许这 6 个键：
`url` / `name` / `category` / `description` / `icon` / `tarball`（外加只读的 `file`）。
写了别的键会被 `validateEntries` 直接报错：

> `unknown field "npm" — an entry may only declare url, name, category, description, icon, tarball.
> ... The npm package is resolved automatically from the repository, not declared here.`

**npm 关联是从 registry 自动探测的**（`probe-npm.mjs` 读仓库的 `package.json.name`，
再查 registry，核对该包 `repository` 是否含本仓库名）。我们的两个字段都已对齐，**下次夜间构建会自动收录**。

### 逐字段说明

| 字段 | 值 | 为什么 |
|---|---|---|
| `url` | `.../tree/main/presets/task-planning-bundle` | 仓库根**没有** `package.json`；`dsh.bundle` 在子目录。对方 CI 会读 `<sub>/package.json`，指错会直接给出应改成什么 |
| `name` | `TBTNCT/dsh-task-planning-mode#task-planning-bundle` | `#` 前的 owner/repo **必须与 url 完全一致**（对方会校验，防止"链接文字指 A、实际跳 B"）；`#` 后是子路径自由标签 |
| `category` | `workflow`（Workflow & Automation） | 23 个分类里最贴的：产出是「规划 + 提示词 + 任务顺序」。选不准也不会被打回，维护者会直接改 |
| `description.en` | 156 字符，单行 | **必填**。只陈述事实：「按版本迭代轮次提问 → 产出分步规划与提示词 → 自己不实现」——与 `PROMPT.md` 硬约束 ① 逐字对得上，可核 |
| `description.zh` | 57 字 | 可选（不写维护者会补），但写了更好 |


## 二、逐条操作（人工执行）

### 第 1 步：Fork 仓库

浏览器打开 <https://github.com/awesome-dsh-plugin/awesome-dsh-plugin>，
右上角点 **Fork** → **Create fork**（保持默认名即可）。
或用 `gh`：

```powershell
gh repo fork awesome-dsh-plugin/awesome-dsh-plugin --clone=false
```

### 第 2 步：克隆你的 fork 并建分支

```powershell
cd $env:USERPROFILE\Desktop          # 或你习惯的目录
gh repo clone <你的用户名>/awesome-dsh-plugin
cd awesome-dsh-plugin
git switch -c add/tbtnct-dsh-task-planning-mode
```

### 第 3 步：新建条目文件

路径**必须**是（文件名不能改）：

```
data/plugins/TBTNCT__dsh-task-planning-mode--presets-task-planning-bundle.yml
```

内容用上面 §一 的 YAML 原文。PowerShell 写文件（**必须 UTF-8 无 BOM**）：

```powershell
$path = 'data\plugins\TBTNCT__dsh-task-planning-mode--presets-task-planning-bundle.yml'
$yaml = @'
url: https://github.com/TBTNCT/dsh-task-planning-mode/tree/main/presets/task-planning-bundle
name: TBTNCT/dsh-task-planning-mode#task-planning-bundle
category: workflow
description:
  en: 'Adds a "Task Planning" agent preset that asks requirements in versioned rounds, then writes step-by-step plans and prompts without implementing them itself.'
  zh: '为 DSH 增加「任务规划」模式：按版本迭代逐轮提问把需求问清楚，再产出可逐条执行的规划与提示词，自身不实现代码。'
'@
[System.IO.File]::WriteAllText((Join-Path (Get-Location) $path), $yaml, (New-Object System.Text.UTF8Encoding($false)))
```

> 用 `[System.IO.File]::WriteAllText` 而不是 `Set-Content -Encoding UTF8`：
> 本机 PS 5.1 的 `Set-Content` **会写 BOM**（本仓库铁律 8 已记录）。YAML 带 BOM 可能解析异常。

### 第 4 步：本地自查（可选但推荐）

```powershell
npm ci
node scripts/generate-readme.mjs
git status            # 应只看到你的条目文件 + README 的生成改动
```

### 第 5 步：提交并推送

```powershell
git add data/plugins/TBTNCT__dsh-task-planning-mode--presets-task-planning-bundle.yml
git commit -m "Add TBTNCT/dsh-task-planning-mode"
git push -u origin add/tbtnct-dsh-task-planning-mode
```

### 第 6 步：开 PR

```powershell
gh pr create --repo awesome-dsh-plugin/awesome-dsh-plugin --title "Add TBTNCT/dsh-task-planning-mode" --body "Adds a Task Planning agent preset (npm: dsh-task-planning-preset)." --head <你的用户名>:add/tbtnct-dsh-task-planning-mode
```

或浏览器打开你 fork 的分支页，点 **Compare & pull request**。

### 第 7 步：等 CI

依次检查：**条目数 ≤ 3** → **`dsh.bundle`**（读子目录的 `package.json`）→ **仓库年龄 ≥ 1 天** → awesome-lint + 站点构建。
失败会在 PR 评论里**点名改什么**；**在同一分支推送修复即可，不用重开 PR**。

## 三、预期会被问到的点（提前准备答复）

| 可能的质疑 | 我们的答复（都有据） |
|---|---|
| 「是不是纯聚合包？」 | 不是。自带行为：persona 提示词（`PROMPT.md` 9887 汉字）+ 本地工具插件（`estimate_tokens` / `usage_report` 两个工具）+ `planning-templates` skill。不是只列依赖 |
| 「描述里说的版本迭代提问是真的吗？」 | 是。`PROMPT.md` §二 整节为「版本迭代询问法」：先给版本迭代规划表等确认 → 逐版本提问（每版每轮 3–9 题、最多 9 轮）→ 每版确认书 → 总确认书。对方可逐字核 |
| 「真的不实现代码吗？」 | 硬约束 ①「只规划不执行」写在 `PROMPT.md` §零 与 §十五 首尾双写，可核 |
| 「为什么 url 指到子目录？」 | 仓库是多交付物布局（旧机制留档 + 新版 bundle），`dsh.bundle` 声明在 `presets/task-planning-bundle/package.json` |
| 「有没有 npm 包？」 | 有：`dsh-task-planning-preset@1.2.0`，`repository` 已指回本仓库 |
| 「依赖是否指向原作者？」 | 不依赖任何第三方插件包，只用 DSH 自带包 |

## 五、若被打回的常见情形

| 打回理由 | 处理 |
|---|---|
| 文件名不对 | 按 CI 提示的 `expected X.yml` 改名，slug 规则 = `owner__repo--路径中/换成-` |
| 描述不准确 | 对方会逐句对照代码。**只改描述，不要加形容词**；我们的描述已刻意不带营销词 |
| 仓库年龄不足 | 不适用（已 14 天） |
| 分类不贴切 | 一般不因此打回，维护者直接改 |
| CI 说「entry points at the repository root, but root package.json declares no dsh.bundle」 | **说明 url 没写子目录**，改成 §一 的写法 |
