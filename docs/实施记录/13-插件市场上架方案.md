# 实施记录 13：插件市场上架方案（2026-10-27）

> 触发：使用者问「怎么把这个插件上传到插件市场」。
> 结论先行：**DSH 没有「官方插件商店」的后台可以上传**；对使用者可见的两条市场通路
> （DSH 的「发现」标签页 / `dshmarket` 插件市场）**都读同一个社区精选目录
> **awesome-dsh-plugin.com**，收录方式是**给它的仓库提一个 PR，加一个 YAML 文件**。
> 本文记录机制取证、我们的可上架前提核查、以及待提交的具体内容。

## 一、机制取证（每条都有出处）

| 结论 | 证据 |
|---|---|
| DSH 官方只定义「市场索引格式」，不提供上架后台 | `<DSH_SRC>/packages/boot/plugin-market/README.zh.md`：「默认不配置任何索引源，因此在用户添加索引源之前，Host 不发送任何市场请求」 |
| 索引是可自行托管的 JSON 文档 | `<DSH_SRC>/packages/util/plugin-market-index/README.zh.md`：格式 1 校验器；`parseMarketIndex` |
| 「发现」标签页来自可选组合包，且**当前 profile 未启用** | 证据见 §四.3 |
| `dshmarket`（本机已装 1.66.32）的目录源 | `dshmarket/lib/regions.js:63` `CATALOG_OFFICIAL = 'https://awesome-dsh-plugin.com/plugins.json'`；中国区走 npm 包 `dsh-plugin-catalog`（`regions.js:87`） |
| 社区目录的收录方式 | `awesome-dsh-plugin/awesome-dsh-plugin` 仓库 `contributing.md`：「Open a PR that adds **one file**, named after your repo — `data/plugins/<owner>__<repo>.yml`」 |
| 子目录（monorepo）条目的写法 | 同上：「point `url` at the subdirectory and use `owner/repo#subname` as the `name`」 |
| 文件名校验规则 | `scripts/lib/entries.mjs:59-65` `slugFor()`：`owner__repo` + `--` + 目录路径把 `/` 换成 `-` |
| 子包 `dsh.bundle` 会被接受 | `scripts/check-submission.mjs:280-296` `hasBundle(repo, sub)`：先读 `<sub>/package.json`，有 `dsh.bundle` 即通过 |
| 根目录没有 `dsh.bundle` 时的正确处理 | 同文件 318-345：**不是直接拒**，而是要求把条目 URL 指到子包目录 |

**已实测的关键一步**：市场卡片给出的安装命令形态是
`dsh plugin --profile web add github:owner/repo#path:/presets/task-planning-bundle`。
用 pnpm 直接验证该 spec 可用：

```
pnpm add "github:TBTNCT/dsh-task-planning-mode#path:/presets/task-planning-bundle"
→ + dsh-task-planning-preset 0.1.0（6.8s）
→ node_modules/dsh-task-planning-preset 内含 PROMPT.md / cordis.patch.yml / plugins / skills
```

即：**子目录上架后，别人能真的装上**，不是只能看不能用。

## 三、待提交的文件（一个文件就是全部投稿）

路径（在 awesome-dsh-plugin 仓库里）：
`data/plugins/TBTNCT__dsh-task-planning-mode--presets-task-planning-bundle.yml`

```yaml
url: https://github.com/TBTNCT/dsh-task-planning-mode/tree/main/presets/task-planning-bundle
name: TBTNCT/dsh-task-planning-mode#task-planning-bundle
category: workflow
description:
  en: 'Adds a "Task Planning" agent preset that clarifies requirements by versioned rounds of questions, then writes step-by-step plans and prompts without implementing them itself.'
  zh: '为 DSH 增加「任务规划」模式：按版本迭代逐轮提问把需求问清楚，再产出可逐条执行的规划与提示词，自身不实现代码。'
```

**分类为什么选 `workflow`（Workflow & Automation）**：它产出「规划 + 提示词 + 任务顺序」，
不是 UI、不是工具集、不是主题；`workflow` 是 23 个分类里最贴的一个
（分类取值见 `scripts/lib/entries.mjs:26` 的 `CAT_IDS`）。

**为什么 YAML 里给描述加了引号**：`contributing.md` 明确警告「含 `: ` 的必须加引号，
否则 YAML 会当成嵌套键」。我们的英文描述里没有 `: `，但加引号无副作用、可防将来改动踩坑。

## 四、可选加分项（不做也能上架）

### 4.1 `screenshots.json`（推荐）

在 `presets/task-planning-bundle/screenshots.json` 放 1–8 张图，市场详情页会展示。
**必须在 GitHub 托管**（`raw.githubusercontent.com` 等），第三方图床会被拒。
我们现有两张截图在 `docs/实施记录/`（预设卡片），可复制作图源；
但它们是**内部验证产物**，需先确认不妨碍隐私门（08 审计已人工确认过画面干净）。

### 4.2 发 npm（可选，只影响「下载量」显示）

- 发布不影响收录（`contributing.md`：「发不发布都不影响收录」）。
- 若发：包名 `dsh-task-planning-preset`（npm 上当前 **未被占用**，实测 404），
  `repository` 字段必须指回本仓库，否则不关联。
- 注意：`dsh.bundle` 在子目录里，npm 包应**以该子目录为包根**发布
  （即 `npm publish presets/task-planning-bundle`），否则里面没有 `cordis.patch.yml`。

### 4.3 DSH 自带「发现」标签页（另一条路，当前不可用）

- 需要启用可选组合包 `@deepseek-ai/dsh-experimental-plugin-market-bundle`。
- **本机 profile 未安装也未启用该包**（`~/.dsh/profiles/desktop/node_modules` 下没有它，
  `package.json` 的 15 个 bundle 里也没有）→ 界面里没有「发现」标签页。
- 即使启用，也**没有官方索引源**，需要自己添加 URL —— 我们没有自建索引，故暂不走这条。

## 五、操作步骤（人工执行，含 AI 不能代做的部分）

1. **Fork** `awesome-dsh-plugin/awesome-dsh-plugin`（用你自己的 GitHub 账号）。
2. 在 `data/plugins/` 新建 §三 那个文件（文件名必须一字不差）。
3. 提 PR，标题形如 `Add TBTNCT/dsh-task-planning-mode`，一个 PR 只加 1 条。
4. 等 CI：会依次检查条目数 ≤3 → `dsh.bundle` → 仓库年龄 → awesome-lint/站点构建。
   失败会指名改什么，**在同一分支推送修复即可**，不用重开 PR。
5. 人工 review 会读仓库核对描述；合并后站点自动重建，`dshmarket` 与索引随之收录。

**AI 的边界**（按本仓库铁律 11）：fork、提 PR、合并都是**账号行为**，只能由使用者本人做。

## 六、风险与预期管理

- **收录不等于安全审查**：`contributing.md` 明说收录只是常识性检查，不是审计；README 顶部有警告。
- **索引无签名**：市场里的标题/作者是「声明」，不是 DSH 验证过的。
- **可能被要求改分类**：维护者会直接把分类改对，不会因此打回。
- **描述会被逐句核对**：这是最常见的打回原因。我们上面那句只陈述「按版本迭代提问 → 产出规划与提示词 → 自己不实现」，与 `PROMPT.md` 的硬约束 ① 一致，可核。
- **上架不等于安装量**：DSH 用户主要是从 `dshmarket` 逛；有截图和 npm 下载量会更容易被点到。
