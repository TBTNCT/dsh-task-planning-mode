## 2. 接线：为什么**不能**用任务书正文给的 `!!js` 写法（本次最重要的技术结论）

### 2.1 任务书建议的写法

任务书 §一 建议：

```yaml
prefix: !!js "process.getBuiltinModule('node:fs').readFileSync(new URL('PROMPT.md', baseUrl), 'utf8')"
```

理由是「官方创造模式里用过同一个机制」（`presets/cordis/agent.cordis.yml` 的 `new URL('skills/', baseUrl)`）。

### 2.2 机制：`!!js` 确实拿得到 `baseUrl`，但它的值是 **profile 目录**

只读源码证据（两处，均可在本机安装树复核）：

```text
<DSH_INSTALL>\node_modules\@deepseek-ai\cordis-plugin-loader\lib\index.js:289
  const evaluate = new Function("ctx", "expr", `
    with (ctx) {
      return eval(expr)
    }
  `);

…同文件:689（config 求值入口，用的是**该 entry 自己的 ctx**）
  return interpolate(this.ctx, config);

…同文件:161（EntryTree 把 baseUrl 传下去）
  this.ctx = ctx.extend({ baseUrl: ctx.baseUrl });

<DSH_INSTALL>\node_modules\@deepseek-ai\dsh-app-boot\lib\index.js:1529（boot 设的根 baseUrl）
  ctx.baseUrl = pathToFileURL(dirname(absoluteConfigPath)).href + "/";
```

即：`!!js` 在 `with (ctx) { eval(expr) }` 里求值，所以 **`baseUrl` 在作用域里**；但 `baseUrl` 是
**profile 配置目录**（`dirname(profile/cordis.yml)`），不是本 patch 文件所在目录。

官方创造模式那份能用，是因为它的 `agent.cordis.yml` 是**被 include 的子树**，
`Include` 构造时会把自己的目录设成子树的 baseUrl：

```text
<DSH_INSTALL>\node_modules\@deepseek-ai\dsh-app-boot\lib\index.js:140
  this.ctx.baseUrl = new URL(".", pathToFileURL(this.filename)).href;
```

而**本 bundle 的 `cordis.patch.yml` 是「补丁层」，不是被 include 的子树**：

```text
<DSH_INSTALL>\node_modules\@deepseek-ai\dsh-app-boot\lib\index.js:845-870（loadProfileDirectory）
  const layers = bundles.map((packageName) => {
    const packageDir = resolveBundleDir(binName, packageName, installAnchor, dir);
    const declared = JSON.parse(readFileSync(join(packageDir, "package.json"), "utf8")).dsh?.bundle?.patch;
    const patchPath = join(packageDir, declared);
    return { packageName, packageDir, patchPath, patches: loadOverlayPatches(binName, patchPath) };
  });
```

—— 每个 bundle 的 patch 被**读出来当补丁列表**，再 `composeEntries` 应用到 profile 根 entry list。
所以 bundle 里插入的行，其 `baseUrl` 仍是 profile 目录。**「相对谁」在补丁层里没有宿主。**

### 2.4 最终采用的接线

```yaml
- id: persona
  name: '@deepseek-ai/dsh-persona'
  config:
    prefix: !!js "process.getBuiltinModule('node:fs').readFileSync(process.getBuiltinModule('node:module').createRequire(new URL('noop.js', baseUrl)).resolve('dsh-task-planning-preset/PROMPT.md'), 'utf8')"
    suffix: Your working directory is {{cwd}}.
```

**为什么不退回「内联进 YAML 块标量」**：按包名解析这条路已经实测走通，且
① 与同一文件里插件行 `name: dsh-task-planning-preset/plugins/token-estimator/index.js` 走的是**同一条解析基准**
（profile 的 `node_modules` 里有本 bundle 的 link，任务 03 已实测）；
② 不含任何绝对路径 → 可开源分发（任务 08 要求）；
③ `PROMPT.md` 仍是**可被 VS Code 编辑、可 diff、可 git 管理**的独立文件（任务书的原始诉求）。
内联方案只在 §2.4 这条路**运行期**被证伪时才启用（回退判据见 §6 偏离 2）。

`validate-bundle.cjs` 报的 `YAMLWarning: Unresolved tag: tag:yaml.org,2002:js`（line 63 的 `prefix`、line 86/90 的 `disabled`）

## 6. 偏离计划之处（逐条）

   任务书正文要求把 `PROMPT.md` 写到 `presets/task-planning/`（0.1.x 目录机制）。

   所以 `PROMPT.md` 落在 bundle 内，`presets/task-planning/` **保持 0.1.x 留档原样未改**（与任务 02/03 一致）。

   按任务书要求**不在这上面反复试超过两轮**。
3. **硬约束 ⑪ 里的参照项目路径改为泛指**。
   ⑪ 原文的括号里带了一个本机绝对路径（`<REFERENCE_PROJECT_PATH>`）。
