### B3 `dsh-boot-animation\entry.js` 前 80 行

```js
// dsh-boot-animation — Host half.
//
// Two contributions, both required for the overlay to exist at all:
//
//  1. a webserver route serving the clip pool (bytes from ./assets/videos) and
//     a same-origin manifest naming them, and
//  2. an index injection whose head row installs the screen before the shell
//     boots.
//
// The head row is the whole reason this is a plugin rather than a client
// component: the kernel constructs its own boot page synchronously in
// `AppWebEntry`'s constructor, which runs from the shell module script, so only a
// parser-blocking index row executes early enough to pre-empt it.
//
// Settings are the third contribution, and under DSH 0.2.0-rc.2 they are
// DECLARED rather than registered. The Host `settings` service has no
// `register(ns, schema)` method any more: a settings namespace IS a plugin entry.
// `@deepseek-ai/dsh-settings` describes every running entry whose resolved export
// carries a `Config` schema — `entry.fiber.runtime.Config`, filled from this
// module's `Config` export by `RegistryService.plugin` — keyed by the entry id in
// the profile patch, here `boot-animation`. The browser half pairs with that same
// string, through the client `configForms` service, which exposes only the
// namespaces the Host actually serves. Two consequences are load-bearing:
//
//   * `Config` must be a property of the module namespace object, so the schema
//     package has to resolve at module-evaluation time. The previous lazy import
//     degraded to "no settings card"; a static import fails the whole module,
//     which is why `@deepseek-ai/schemastery` is a peer dependency — the host
//     supplies it — and never a vendored copy.
//   * `describe()` reports only an entry whose Config projects a non-empty form,
//     and that projection keeps only fields marked `.volatile()`. A schema with
//     no live field is invisible to the settings page; see `LIVE_CAPABLE`.
//
// The patch id is therefore part of the contract: renaming the `- insert:` id in
// cordis.patch.yml moves the namespace and silently orphans the browser card,
// whose key is the same string.

import { readdir, stat, open } from 'node:fs/promises'
import { createReadStream, readFileSync } from 'node:fs'
import { fileURLToPath } from 'node:url'
import { basename, extname, join, resolve, sep } from 'node:path'
import z from '@deepseek-ai/schemastery'

/**
 * Absolute path of the pre-boot screen source.
 *
 * The script is read per index render rather than once at module load. Reading it
 * at load time would pin the served script to whatever the file held when the
 * process started, so editing a label or the exit fade would require restarting
 * dsh — the one operation this plugin's whole design tries to avoid asking for.
 */
const BOOT_SCREEN_PATH = fileURLToPath(new URL('./src/boot-screen.js', import.meta.url))

/** Video container extensions the pool accepts, in discovery order. */
const VIDEO_EXTENSIONS = new Set(['.mp4', '.webm', '.m4v', '.mov'])

/** Route prefix both the manifest and the clip bytes live under. */
const ROUTE = '/plugins/dsh-boot-animation'

/**
 * The values the screen runs with when the applied config does not carry one.
 *
 * With a `Config` schema present these are unreachable in practice: Cordis
 * validates the raw profile row against the schema before `apply` runs, so every
 * field arrives already defaulted and an absent settings document and an empty
 * one resolve identically. They are kept anyway, because the fallback must not

 */
const DEFAULT_SETTINGS = {

关键情报（来自这段注释 + 代码，价值高）：
- 宿主端插件可以拿到**两条扩展点**：`webserver` 路由（`/plugins/<包名>/...`）与 **index 注入**（head 行，parser-blocking，能在 shell 模块脚本之前执行）。
- **设置项是「声明」而非「注册」**：模块命名空间导出 `Config`（schemastery schema）即自动成为设置命名空间，键 = profile patch 里的 entry id。
- 只有标了 `.volatile()` 的字段会出现在设置表单里。
- 插件路由命名惯例：`ROUTE = '/plugins/dsh-boot-animation'`（**与包名强相关**）。

// Rebuild lib/client.js from src/client.js.
//
// The browser bundle is the source wrapped in the shell's module-loader call.
// Keeping the build here — rather than in a bundler — is deliberate: this half
// imports nothing (React arrives through the factory's `require`), so there is
// nothing to resolve and nothing to tree-shake. The wrapper is the whole build.
//
//   window.__ModuleLoader__.load({ id: "dsh-boot-animation", factory: (require) => {
//   var module = { exports: {} }; var exports = module.exports;
//   <src/client.js verbatim>
//   return module.exports; } });
import { readFileSync, writeFileSync } from 'node:fs'
import { dirname, join } from 'node:path'
import { fileURLToPath } from 'node:url'

const root = dirname(fileURLToPath(import.meta.url))
const id = JSON.parse(readFileSync(join(root, 'package.json'), 'utf8')).name

const head = `window.__ModuleLoader__.load({ id: ${JSON.stringify(id)}, factory: (require) => {\n`
  + 'var module = { exports: {} }; var exports = module.exports;\n'
const tail = '\nreturn module.exports; } });\n'

const source = readFileSync(join(root, 'src', 'client.js'), 'utf8')
if (source.includes('return module.exports; } });')) {
  throw new Error('build-client: src/client.js already carries the loader tail; it is source, not a bundle')
}

const bundle = head + source + tail
writeFileSync(join(root, 'lib', 'client.js'), bundle)
console.log(`build-client: lib/client.js written (${String(bundle.length)} chars from ${String(source.length)})`)
```

**这是客户端插件「最小可行打包格式」的直接证据**：客户端产物必须是
`window.__ModuleLoader__.load({ id: "<包名>", factory: (require) => { ... return module.exports } })`
包一层；`id` 用包名（`package.json.name`）。

### D2 与任务 B 两个手写插件的对照

| 维度 | dsh-whale-widget | dsh-boot-animation | maid-atelier（npm 发布） |
| --- | --- | --- | --- |
| 语言 | JS（ESM） | JS（ESM） | TS，用 `tsdown` 构建 |

| 客户端入口 | 无（宿主自建路由下发 assets JS） | `exports["./client"]`（条件对象形式） | `exports["./client"]`（字符串形式） |
| `dsh.client` | 无 | `{ platform: "web" }` | `{ inject: [], platform: "web" }` |
| `dsh.bundle.patch` | `./cordis.patch.yml` | `./cordis.patch.yml` | `./cordis.patch.yml` |
| `scripts` | 无 | 无 | `build`/`test`（构建期用，运行时无关） |
| scoped 发布 | 否（裸名） | 否 | 是，且 `publishConfig.access: public`（scoped 包必需） |
| 额外清单文件 | — | — | `skin.json` / `skin.build.json`（皮肤包自有约定，非 DSH 规范字段） |
| peer 依赖 | 无 | `@deepseek-ai/schemastery` | `@deepseek-ai/cordis` |
| 构建产物含 sourcemap | — | 无 `.map` | `lib/client.js.map`（5771 B） |

三点可直接复用的结论：
1. **`exports["./client"]` 既接受字符串也接受 `{ default: "..." }` 条件对象**（C5 代码里的 `clientExportOf`）。
2. **`inject: []` 是合法且被实际发布的写法**（maid-atelier 就这么发），说明该字段可省可空。
3. scoped 包发布必须 `publishConfig.access: public`，否则默认私有导致 404；裸名包（whale-widget）不需要。

## 总体结论（供后续开发直接采用）

1. **本机环境**：Node 24.20.0 / npm 11.19.0 / 全局 pnpm 12.3.4 / git 2.56.0.windows.1；**无全局 `dsh` 命令**；无代理；registry 均为官方 npmjs；裸 `python` 不可用（须用 `%USERPROFILE%\AppData\Local\Python\bin\python.exe`，3.14.7）。
2. **profile 的真实布局**：`~/.dsh/profiles/{web,desktop}`，各自 `package.json`（`dsh.profile.bundles`）+ `pnpm-workspace.yaml`（`packages: [.]`、`nodeLinker: hoisted`、`autoInstallPeers: false`）+ `pnpm-lock.yaml`；store/virtualStore 在 `<DSH_HOME>`。desktop profile 由 Electron 应用独占管理，命令行 `--profile desktop` 被设计性拒绝。
3. **插件最小形态**：`package.json` 里 `type: module` + `main` + `dsh.bundle.patch` + 一个 `cordis.patch.yml`（`- insert: [{ id, name }]`）。要做客户端 UI 再加 `exports["./client"]` + `dsh.client.platform`，产物必须用 `window.__ModuleLoader__.load({ id: <包名>, factory })` 包装并预先构建。
4. **`package.json.dsh` 的合法键只有 6 个**（`bundle`/`profile`/`client`/`configTrees`/`sessionFormatMigration`/`moduleFallback`），第三方插件实用的是 `bundle`(+`client`)；**没有 `preset`、没有 `skill` 键**。
5. **本地开发用 `link:`**：`profiles/desktop/package.json` 已是 `link:<PLUGINS_DIR>/<pkg>`，实际经 `%USERPROFILE%\plugins` 这个 **Junction → <PLUGINS_DIR>** 落地；改源文件立即生效，但**不可移动/重命名源目录**（否则要重新 add）。
6. **宿主端扩展点**（来自 boot-animation 注释）：webserver 路由 `/plugins/<id>/...`、index 注入（parser-blocking head 行）、设置项靠导出 `Config`（schemastery）**声明**；entry id 即设置命名空间 key。
7. **源码阅读路径修正**：任务书给的 `app.asar\dsh` 不存在；应读 `%USERPROFILE%\.dsh\profiles\node_modules\@deepseek-ai\*`（0.1.5-rc.2，200+ 包）。
