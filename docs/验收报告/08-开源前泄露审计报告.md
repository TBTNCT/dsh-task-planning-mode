### 1.5 清理：重写全部提交历史（41 个提交）

- 原因：**每个提交的作者与提交者都是真实邮箱**，推上公开仓库后永久可见、可被反查（规范第 ④ 类）。
- 做法：`git filter-branch --env-filter`（换中性身份）+ `--tree-filter`（跑 `privacy-sanitize.mjs` 占位化、
  并把 1.4 的内部产物从**全部历史**中移除）+ `--tag-name-filter cat`。
- 中性身份：`dsh-task-planning-mode contributors <noreply@example.com>`；AI 提交保留 `dsh-agent <agent@local>`。
- **提交信息与时间戳未改**；41 个提交一一对应，旧→新 hash 对照见 `docs/实施记录/06-历史重写对照表.md`。
- 收尾：删除 `refs/original` → `git reflog expire --expire=now --all` → `git gc --prune=now`；
  `git fsck --unreachable` 无输出（旧对象已不可访问）。
- **备份**：重写前做了完整 bundle（`git bundle create --all`，646 KB，`git bundle verify` 报
  "records a complete history"），存本机临时目录、未入库。
- **偏离计划之处**：重写历史会改变全部 commit hash，因此本台账 01–06 行与各报告里引用的旧 hash 全部失效——

## 五、给下一个任务的注意事项

1. **门禁命令是 `node tools/privacy-scan.mjs`，退出码 0 才算过**；它默认**连历史一起扫**，
   所以「删掉最新提交里的密钥」不会让它变绿——必须重写历史。
2. **`tools/privacy-local-rules.json` 永远不要 `git add`**。它已被 `.gitignore` 排除；
   里面是本机真实用户名/邮箱/盘符布局。要加新规则，通用规则写 `privacy-rules.json`，本机值写这个文件。
3. **内部产物不要再 `git add` 回来**：`demo/_自测*/`、`demo/_验收/`、`notepad-app/`、`**/.dsh-acl-report/`。
   文件留在磁盘上没问题，进公开仓库不行。
4. **本仓库当前 commit 身份是中性身份**（`git config --local` 已设）。这是刻意的，不要「顺手改回去」，
   否则新提交又会带上真实邮箱。
5. **扫描器覆盖不到的部分必须人工看**：截图、录屏、日志、Office 文档属性、压缩包。本次 2 张 PNG 已确认干净；
   以后新增截图，发布前要重新过一遍。
6. **本插件的模式本体已含这条规范**（`PROMPT.md` ⑫ 硬约束，哨兵 `v8`）：以后用本模式规划**任何**要开源的项目，
   它都会自动规划一个「开源前隐私检查」任务放在发布任务之前。改 `PROMPT.md` 时不要把 ⑫ 删掉，
   也不要把哨兵值改回去（哨兵是「提示词是否真的生效」的判据）。
7. 推送前请再跑一次门禁（历史已重写，但推送前的任何新提交都会重新进入历史）。
8. **`git config --global` 也要看一眼**（规范 §四 步骤 0.5）：只设 `--local` 能保住本仓库，
   但全局那两行是"根因"——不改的话，你以后每建一个新仓库都会重新泄露一次。本次已按方案 A 改为
   `这里有只小西琳 <325988531+TBTNCT@users.noreply.github.com>`。
