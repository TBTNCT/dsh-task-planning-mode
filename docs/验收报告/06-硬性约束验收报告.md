## 三、返工记录（改前 → 改后）

> 详细对照另见 `docs/验收报告/06-返工记录.md`

### 3.1 返工一（对应约束 3）：估算表必须落盘

- **改前**：§零③只说「每次规划必须输出估算表」，未说写到哪里 → 两次实际规划都只在对话里给表，产物零落盘。
- **改后**：§八新增第 6 条「**估算表必须落盘**：默认写进 `docs/工作流程/00-总览与使用说明.md`，大项目可单独成文；对话数字必须与落盘一致。这是硬要求：执行会话只看产物，不看规划对话。」§零③、§十二.5 同步补「落盘」判定。
- **哨兵**：v6 → v7（已触碰 `cordis.patch.yml`，mtime+size 已变）。

### 3.2 返工二（对应约束 3 的规格漏洞）：「拒绝立项」出口没有条文

- **现象**：需求 B 被整体拒绝，拒绝质量高（量级+原因+降级路线齐全），但该出口在 `PROMPT.md` 里**没有任何条文**——两次跑可能形态完全不同（这正是本模式要消灭的「两次不一样」）。
- **改后**：§八新增第 7 条「拒绝立项是正式出口，但回复必须含三件事：①规模感受（量级判断）②为什么超出（工程性质，说人话）③降级路线（2–3 条）。三件不全视为未完成。」§十二.5 自检同步。

### 3.3 验收清单自身的设计缺陷（本任务流程问题，如实登记）

需求 B 的检查点原设计假定模式会走「估算→拆分告知」路径，未考虑「整体拒绝立项」这一实际更合理的出口。发现后已即时修正清单口径（回填前修正，见清单 §约束 3 的「实际执行记录」引用块），未影响判定独立性——判定依据是**修正后口径 + 人工回填的完整原文**。
