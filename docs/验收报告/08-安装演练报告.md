## 〇、先读这一节：任务书的判据与本机机制不符（必须如实记录）

任务书写的是：

> 删掉用户层副本 `%USERPROFILE%\.dsh\.agent-presets\task-planning\` → 按 README 的路线 A 步骤重装一次
> → 新开 DSH 会话确认「任务规划」重新出现

**这套判据基于 DSH 0.1.x 的「目录型」机制。** 本机桌面端跑的是 **0.2.x 声明式机制**，机器侧已核实：

- 模式实际来自 **profile 里安装的 bundle 包** `dsh-task-planning-preset`
  （= `link:<仓库根>\presets\task-planning-bundle`，已列入 `dsh.profile.bundles`）；
- `%USERPROFILE%\.dsh\.agent-presets\task-planning\` 是 **0.1.x 的死数据** —— 0.2.x 的 preset 注册表
  **不扫描任何目录**（证据：`docs/实施记录/01-预设机制冲突-运行时版本不符.md`、`docs/调研/03-preset机制-新版.md`）。

⇒ **「删掉用户层副本」不会让模式消失**，原判据在 0.2.x 上不成立（删了模式照旧在）。
因此本报告把演练拆成两段，分别证明两件事：

| 段 | 证明什么 | 为什么必要 |
|---|---|---|
| **演练 A（主）** | 真实安装路径可用：**卸载 bundle → 模式消失 → 重装 → 模式出现** | 这才是"别人在新机器上也能装上"的证明；也是 08 验收标准里"步骤可复现"的唯一实证 |
| **演练 B（附）** | 「用户层副本是死数据」由**文档结论**升级为**运行期实测** | 把本项目最反直觉的一条结论钉死；同时验证 `install.ps1 -LegacyCopy` 可用 |

> **记录纪律**：本报告要进公开仓库。粘贴原始输出时，请把本机绝对路径替换成占位符
> （`<仓库根>`、`%USERPROFILE%`、`<DSH_HOME>` 等，约定见 `docs/优化提示词/02-开源前隐私规范.md` §三）。
> 粘贴前可跑一次 `node tools/privacy-scan.mjs` 自查。

## 二、演练 A：真实安装路径（**人工执行**）

> 目标：证明「一个陌生人拿到这个仓库，能装上、能看到模式」。
> 全程约 5–10 分钟。**每一步的原始输出都请粘贴到 A.5**，不要只写"成功了"。

### A.0 演练前备份（强烈建议，一条命令）

卸载会改 profile 的 `package.json` 与 `pnpm-lock.yaml`。先各留一份副本，万一重装失败可以对照恢复：

```powershell
$h = "$env:USERPROFILE\.dsh\profiles\desktop"
$b = "$env:TEMP\dsh-drill-backup"
New-Item -ItemType Directory -Force -Path $b | Out-Null
Copy-Item "$h\package.json"   "$b\package.json.bak"   -Force
Copy-Item "$h\pnpm-lock.yaml" "$b\pnpm-lock.yaml.bak" -Force
Get-ChildItem $b | Select-Object Name, Length
```

- [ ] 已备份（⬜ 待回填：备份目录与两个文件大小）

### A.1 卸载模式（桌面端 UI）

1. 打开 DSH 桌面端 → 左侧栏 **插件**。
2. 找到 **`dsh-task-planning-preset`** 那张卡片（**确认是这一张**，不要点到皮肤或 whale 组件）。
3. 点 **卸载**，等 pnpm 跑完。

- [ ] 已卸载（⬜ 待回填：卸载过程有无报错；若有，粘贴原文）

### A.2 确认「消失」（重启 + 新开会话）

1. **完全重启桌面端**（不是关窗口，是退出进程再启动）。
2. **新开一个会话**，打开模式选择器。

- [ ] 模式选择器里**已看不到**「任务规划」← 这是本段的关键判据
- ⬜ 待回填：看到/没看到；若有截图，存 `docs/实施记录/` 并在下面写文件名

### A.3 重新安装（桌面端 UI）

1. 左侧栏 **插件** → **添加插件**。
2. 在包名框里粘贴**本仓库 bundle 目录的绝对路径**（`install.ps1` 会替你打印这一行）：

   ```text
   <仓库根>\presets\task-planning-bundle
   ```

3. 等界面读出包名 `dsh-task-planning-preset` 与版本号，点 **安装**，等 pnpm 跑完。
4. 点 **立即启用**。

- [ ] 已安装并启用（⬜ 待回填：界面读出的包名与版本；有无 `ERR_PNPM_UNEXPECTED_STORE` 等报错原文）

### A.4 确认「重新出现」+ 哨兵值（重启 + 新开会话）

1. **完全重启桌面端**。
2. **新开一个会话**，模式选择器里应出现「**任务规划**」，且卡片**没有**「加载失败」红标。
3. 选进「任务规划」，**问一句**：「当前哨兵值是多少」。
4. 期望回答：逐字复述 `v8`（这一问同时闭合了任务 08 遗留的「哨兵 v7 → v8 未做运行期验证」）。

## 四、失败处置与回滚

| 症状 | 处置 |
|---|---|
| 卸载后**重装失败**，模式彻底不见 | ① 用 A.0 的备份对照 `package.json`；② 在插件管理器里重新粘贴同一路径安装；③ 仍失败则把报错原文记下来，**不要手改 profile**（属铁律 12 禁区），交人工裁决 |
| 安装报 `ERR_PNPM_UNEXPECTED_STORE` | 修法见 `presets/task-planning-bundle/README.md` 第二节（本机已修过一次，若复发说明那行 `storeDir` 不在了）。失败是安全回滚的：pnpm 会恢复 `package.json` 与 `pnpm-lock.yaml` |
| 模式卡片出现但带「加载失败」红标 | 插件页有该组合包的报错，**把原文抄回来**（铁律 11）；常见原因是某行缺必填 config 字段 |
| 模式出现但哨兵不是 `v8` | 说明 persona 没有重新读取 `PROMPT.md`：确认 `cordis.patch.yml` 被"触碰"过（mtime+size 变化），再重启 |
| 误删了别的 bundle（皮肤/whale） | 按 A.0 备份对照恢复，或在插件管理器里重新添加对应包 |
