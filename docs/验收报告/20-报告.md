## 四、关键设计取舍（为什么这么做）

### 4.1 C1 判的是「量级口径」，不是「三处都列三组数字」——任务卡判据的事实误设

任务卡 C1 写「比哪几处：工具实算 vs `PROMPT.md` §七 样例表 vs `00-插件提示词-token估算器.md` 里写的数字 / 三处数值互相吻合（四舍五入到两位小数后一致）」。现场事实是：

- `PROMPT.md` §七 只列了 (a)(b) 两组样例 + 一个合计行，**没有 (c) 组**；
- `00-插件提示词-token估算器.md` 是**接口契约文档**，全文唯一与 ×20 后数字有关的是 `:67`「校准前约 4.6M–14.5M → 校准后约 92M–290M」，**没有 (a)(b) 两组，也没有两位小数**；
- 三组实算数字真正齐全的地方是 `11-报告.md` 与本报告 §3.1，不是 00 文档。

因此按字面「三处两位小数一致」必然判 ❌，且「以 `PROMPT.md` 为准改偏离方」在这里无解——要补的是 00 文档里 PROMPT 根本没有的 (c) 组，属新增内容而非对齐。**经使用者拍板采用量级口径**：只核三处实际写出的数字是否互相矛盾——工具↔PROMPT 逐值全等，00 文档的整数约数与 (c) 取整一致、方向相同，故判 ✅。代价：这条 ✅ 附带一个判据歧义，后续若有人按字面复核会得出 ❌。已在 §7.2 登记，建议任务 30 或后续版本把 C1 判据改写成「工具实算 vs PROMPT §七 逐值一致 + 00 文档量级不矛盾」。**未改动判据文字、未放宽 C4 的逐字一致 / C7 的逐字差异 0 / C6 的七字不差等硬判据。**
