## 六、关键设计取舍

1. **数据块用 `type="application/json"` 但不依赖浏览器执行**：任务书指定了这个形态，浏览器会把它当数据块跳过。脚本改为读 `textContent` → 剥前缀 → `JSON.parse` → 挂回 `window.TASK_FLOW_DATA`。代价是数据必须是严格 JSON（键带引号、无注释、无尾随逗号），好处是「数据接口只有一处」与 C4 对账的接口名两全。
2. **`deps` 写 `id`、悬空依赖过滤 + 自检断言**：渲染层过滤悬空引用避免整页崩，自检层断言悬空数必须为 0 让错误可见，两层分工。
3. **并行同层用「松弛迭代」而不是一次性拓扑**：先按 `deps` 下沉，再把同 `parallelGroup` 拉平到组内最深层，重复到稳定。这样即便有人把并行节点的依赖写成不同深度，也仍强制同层，不会出现「标了并行却上下错开」。
4. **折线用绝对定位细条，不用 SVG / 图形库**：满足零第三方依赖；`resize` 与 `load` 时重画，状态切换时重建以刷新绿色。代价是层间距靠 CSS `gap` 固定，超宽图需要横向滚动（`.flow-wrap` 已给 `overflow-x: auto`）。
5. **预计耗时解析「取区间中值」并显式告警**：`1–2 小时` → 1.5h，`30–55 分钟` → 42.5/60h，`半天` 解析不出就在页面上写明「合计偏小」。按人工决策 3 保持这个口径，不引入中文词表的歧义。
6. **决策 2 用「kind 优先 + 名称回退」**：`kind: "final" | "组装验收" | "gate"` 显式生效；不写 `kind` 时仍走 `gate: true` 与「名字含组装验收」。老数据零改动，且任务书原验收标准仍成立。
