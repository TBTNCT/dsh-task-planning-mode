# dsh-task-planning-mode

给 **DeepSeek Harness（DSH）** 增加一个模式：**「任务规划」**。

> 面向"完全不了解目标行业、但明确知道自己想要什么效果"的人：
> 它把想法**问清楚**，然后拆成可执行的**规划 + 提示词**，并告诉你按什么顺序做。
> **它不实现任何东西**——实现留给标准模式。

## 环境（实测）

Windows · DSH desktop profile（0.1.5-rc.2 实测）· Node v24.20.0 · Git 2.56.0 · PowerShell 5.1 ·
VS Code 1.141.0。macOS / Linux **未实测**。

⚠️ 已知环境坑：**F: 盘为 FAT32**，不支持硬链接，而 DSH 写文件用"临时目录 + 硬链接"做原子替换，
所以在 F: 盘**新建文件的写入会失败**（`write` 工具已实测报错；`edit` 的失败路径未实测）。
本项目统一在 NTFS 盘工作。

⚠️ **未验证的机制结论**：本文档集里"preset 不能携带浏览器 UI"来自源码推导，**未做运行时验证**；
"相对路径行 → 本地插件随 preset 分发"也**未经实测**（任务 03 的第一步就是去实测它）。
凡是这类结论，正文里都会标注"推导，未验证"。

## 产物边界（硬性要求）

1. **用这个模式规划任何项目时**：产出的所有文件（总览、任务文件、通用规范、台账、报告、提示词）
   以及后续每个任务对话产生的文件，**必须全部落在该次会话选定的工作区内**。
   工作区之外的路径（其它项目、用户层目录、DSH 安装目录、临时目录）一律不许写；
   确需在工作区外落地（例如安装工具）必须先告知使用者并取得同意。
2. **`<REFERENCE_PROJECT_PATH>` 只是命名与格式的参考项目，不是要使用的项目**：
   模式运行时不读它、不写它，产出物里不出现它的路径；格式规范来自模式自带的模板
   （`presets/task-planning/skills/planning-templates/`），不是每次去别人的项目里现读。
3. 本项目自身的开发同样遵守这条：产出只写在 `<REPO>` 内，
   **唯一例外**是把 preset 复制到用户层 `%USERPROFILE%\.dsh\.agent-presets\task-planning\` 的安装动作。
